肆 Plugins, opt-in

主程序包里，
一个插件都没有

你可能只想用其中一个，没必要为一两个功能下载全部。所以插件走独立分发：主程序的 plugins\ 与 plugin_store\ 都是空目录， 每个插件只有 10 – 26 KB，想要哪个装哪个。不装插件不影响任何核心功能—— 悬浮球、碎片、任务、笔记、知识库、素材、截图钉屏、软件/网址导航全部照常可用。

Step 01

下载

从 Release 页面的 Assets 区挑一个下载，每个插件只有 10 – 26 KB。

  • 文件名形如 ai-assistant.fpplug

Step 02

放进目录

把 .fpplug 丢进程序目录下的 plugin_store\ 文件夹。

  • 不解压、不改名，源包保持原样

Step 03

安装

启动程序 → 插件中心 → 插件商店 → 点「安装」。

  • 装完即生效，不需要重启

插件能碰到什么，碰不到什么

Boundary

能力要声明，未声明就拒绝

插件必须在 manifest 里显式声明能力，宿主按声明放行；没声明的调用直接返回失败，而不是偷偷放过去。

  • 依赖白名单：只允许 PyQt6 + Python 标准库，ssl / socket / requests 一律拒绝
  • 插件自身拿不到网络库，联网只能走宿主的网络桥
  • 网络桥目前只支持 POST JSON，单次 ≤ 4 MB、超时 ≤ 120 s
  • 未声明能力被调用时返回 False / 0 并记 warning，不会抛异常拖垮程序

Honesty

信任链做透明，不假装有沙箱

插件与主程序同进程运行——这是架构事实，我们不把它说成「沙箱隔离」。能保证的是：能力可见、网络可审计、卸载可彻底。

  • 插件中心卡片上直接标出该插件申请了哪些能力
  • 所有联网请求只把 URL 与耗时写进 app.log，不记录正文
  • 卸载只删 plugins\<插件id>\，源包留在 plugin_store\，想装回来点一次即可
  • 插件私有数据（float_data\plugins\<插件id>\）卸载时不会被删
插件中心负责安装 / 启停 / 卸载 / 商店四件事，改完免重启即生效。 想自己写一个：依赖只允许 PyQt6 + 标准库，用 python tools/pack_plugin.py plugins/<插件目录> 打成 .fpplug 即可分发安装。 完整插件契约（能力声明、知识库接口、AI 动作协议）属内部资料，需要可开 Issue 索取。

伍 Optional AI

AI 是可选件，
而且默认不联网

AI 助手走外置插件，不是主程序的一部分。不装 AI 插件、不填 key、不开本地服务时， 程序其余功能与「从没听说过 AI」的版本完全一致。装了也由你决定它连哪里、能不能出网。

Backend 01

云端 API

走 OpenAI 兼容协议，填地址 + Key + 模型名即可，DeepSeek、硅基流动这类服务通吃。

  • 地址 / Key / 模型三项可改
  • Key 明文本机存储，不上传
  • 接回环地址时可留空

Backend 02

接 Ollama

本机已经跑着 Ollama 的话，指向它就行，不用额外装东西。

  • 默认地址 127.0.0.1:11434
  • 模型由 Ollama 自己管
  • 完全离线，数据不出机

Backend 03

自带本地推理

程序自己拉起 llama-server，浏览选择 exe 与 .gguf 模型，点一下启动。

  • 显卡全量卸载（-ngl 99）
  • 退出程序自动结束，不占残留显存
  • 本地模式断网可用，数据不出机

AI 总配置

一处配置，多插件共用

设置页里配好后端，再勾选授权哪些 AI 插件接入——接入的插件直接读这套地址与 Key，改完即生效，无需重启；没勾选的插件继续用各自私有配置。

  • 云端 / 本地两种模式，切换即显示对应配置区
  • 本地推理由宿主统一拉起，一处启动、所有接入插件共用
  • 「保存并测试连接」一键落盘 + 探活

Diagnostics

连不上时，告诉你为什么

探活结果直接写在状态行上，不同故障给不同提示，不用自己猜是 key 错了还是服务没起。

  • 401 → Key 无效或未填
  • 404 → 地址或模型名不对
  • 超时 → 地址不可达 / 本地服务未启动
  • AI 动作解析失败时整块不执行，不会「猜着执行一半」
隐私立场（写进代码注释里的那种）：不做遥测、不做崩溃自动上报、不做应用内自动下载更新。 联网只发生在你装了联网插件、或主动点「检查更新」时；网络桥只把 URL 与耗时写进日志，不记正文。 这个立场不会因为版本升级而改变。

柒 Under the hood

好看的皮囊，靠谱的里子

UI / 业务 / 数据三层解耦，每一处异常都有兜底——工具软件，稳定是第一颜值。下面这些不是宣传话术，是代码里真实存在的模块。

atomic_write

原子写入

所有数据先写临时文件再 os.replace 落盘，写一半断电也不会留下损坏文件。

single_instance

单实例防护

Windows 互斥量防重复启动，双击多少次都只有一个实例在跑。

schema_version

数据版本与迁移

每个 JSON 数据文件带 schema 版本号与迁移注册表，旧数据升级打开无损。

corrupt_fallback

损坏自动回退

数据 JSON 解析失败时先备份成 .corrupt.bak 再回退默认，不静默丢数据。

docx_sync

外部修改检测

mtime + sha1 双指纹识别外部改动，段落级 hash 比对内容变更。

exception_hook

全局异常钩子

出错弹窗告诉你原因并写进 app.log，绝不静默崩溃；下次启动能感知上次未正常退出。

geometry_guard

位置兜底

分辨率变化、多屏插拔、显示器漂移之后，窗口位置自动兜底，永远找得回来。

clipboard_lru

历史上界

剪贴板历史上限可配（默认 200 条），LRU 自动淘汰，内存占用有明确上界。

theme_engine

双主题引擎

QSS 模板 + 颜色字典统一管理浅色 / 深色两套配色，跟随系统主题，对比度有测试护栏。

拾 Questions

常见问题

怎么装？三步够吗？
比三步还少：下载压缩包 → 解压到任意文件夹（建议别放 C:\Program Files，放桌面或 D 盘都行）→ 双击 FloatPulse.exe。悬浮球常驻桌面角落，主窗口从球上右键唤起；点窗口的 ✕ 默认收进托盘而不是退出。
需要先装 Python 或其他运行环境吗？
不需要。所有依赖（含 PyQt6）都打包在程序文件夹里，开箱即用。这也是整个文件夹有 75 MB 的原因——它把运行环境整个背在身上，替你省掉配环境的麻烦。
我的数据存在哪里？
看你是哪种安装方式，程序按发布形态双轨解析：zip 便携版数据留在 exe 同目录的 float_data\，解压即用、随目录整体移动；安装版（setup.exe）数据走 %APPDATA%\FloatPulse\float_data\，与安装目录解耦——升级或重装换目录数据不跟随丢失。里面是 JSON 明文 + 知识库 docx，没有数据库、没有加密黑盒，随时可以自己备份、自己看。
它会偷偷联网吗？
不装联网插件、不用 AI 时，没有任何云端依赖，断网状态下所有功能照常可用。装了带「网」标记的插件后，请求也只能经宿主的网络桥发出——插件自身拿不到网络库，未声明网络的插件联网调用会被直接拒绝；每次请求只把 URL 与耗时写进 app.log，不记正文。
插件为什么不做进安装包里？
因为你可能只想用其中一个。为了一两个功能下载全部没必要，所以插件走 Release 附件的独立下载，每个只有 10 – 26 KB。主程序包里的 plugins\ 与 plugin_store\ 都是空目录，不装插件不影响悬浮球、碎片、任务、笔记、知识库、素材、截图钉屏等任何核心功能。
卸载干净吗？会留残留吗？
便携版把程序文件夹删掉就完成了。有一点必须提前说明：插件的私有数据不会被卸载删除（float_data\plugins\<插件id>\，安装版在 %APPDATA% 下同样保留），这是故意的——避免你卸载一个插件时连带丢掉它记的东西。没有注册表项、没有后台进程残留。
换电脑怎么办？
便携版：整个文件夹拷走即用，碎片、笔记、任务、知识库一起搬家。安装版：把 %APPDATA%\FloatPulse\ 一起带走即可，或直接用它自己的导出（笔记 / 碎片 / 任务可写进 Obsidian vault）。
和我已经在用的剪贴板 / 截图工具有什么区别？
剪贴板工具只管「收」，FloatPulse 把收、存、翻出来再用做成了闭环：碎片能合并成笔记、段落能存进知识库、任务能直接在球上记、截图能钉屏批注，最后还能导出进你自己的知识库。不替代谁，只是把散落的动作接成一条线。全局文件搜索这类做不过别人的事，我们直接不做——交给 Everything 和 Flow Launcher。
常驻后台会不会拖慢电脑？
它常驻的部分只监听剪贴板事件和鼠标位置，不带联网服务、不做后台扫描。空闲 3 秒后会吸边隐藏；剪贴板历史有明确上限（默认 200 条，LRU 自动淘汰），临时素材也有数量与体积上限，内存占用有上界。普通办公本长期挂机没有压力。
AI 一定要联网吗？
不一定。三条路：① 云端 OpenAI 兼容 API（要联网）；② 接本机已经在跑的 Ollama（127.0.0.1:11434）；③ 由程序自己拉起 llama-server + 本地 .gguf 模型。后两种全程离线、数据不出机。不装 AI 插件时，这些配置项完全不参与运行。
