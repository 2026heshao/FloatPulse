# 站内搜索（kb-search）

一个框，搜**本程序里的全部文字**：知识库段落、笔记、碎片、任务。按相关度排序，命中处加粗着色。

和「全局文件搜索」不是一回事——那是明确不做的（交给 Everything / Flow Launcher）。本插件**只索引宿主自己的数据**，不扫硬盘、不建全盘索引，所以它是秒出结果、随开随用的。

## 怎么用

1. 打开页面：主窗口左栏「🔍 站内搜索」，或按 **Ctrl+Alt+F** / 悬浮球右键「🔍 站内搜索」
2. 在输入框里打字，**边打边搜**（停顿约 0.2 秒后出结果）
3. 结果按相关度从高到低排；每条显示 `[数据源] 标题`、右上是相关度分数、下面是命中片段

### 支持的输入

| 输入 | 行为 |
| --- | --- |
| `月报 归档` | 多词，**只要命中一个词就算召回**，命中越多排越前 |
| `太原家政` | 中文短语，词典里没有的自造词照样能搜到（靠字符 bigram 兜底） |
| `bm25-index` | 英文 / 数字 / 版本号 / 路径 / 邮箱 / 时间 `09:30` 整体当一个词，不被标点切碎 |
| `２０２６ＡＢ` | 全角字符自动归一（从 Word、微信粘贴进来时很常见），搜得到 |
| `the report` | `the / a / of` 这类英文虚词自动忽略，不干扰排序 |

标题和正文一起进索引：搜任务名能搜到，搜任务备注也能搜到；任务的截止日也参与匹配（可以拿 `2026-09` 一次捞出一批）。

## 索引是怎么维护的

- **每次切入这个页面会自动重建索引**，所以刚记的笔记、刚改的知识库段落立刻就能搜到
- 也可以在页面上点 **「🔄 重建索引」**（数据量大或怀疑索引没跟上时用），重建完会弹提示告诉你索引了多少条
- 页面顶部那行一直显示当前状态：`已索引 N 条 ｜ 检索项 M 个`

## 权限与边界

- **本插件只读**：manifest 里的 `capabilities` 是空数组，它没有任何写入能力，不会改动你一条数据
- 数据来源只有四个：知识库段落、笔记、碎片、任务。**其它插件产生的内容不在索引里**（插件之间互相看不到数据）
- 单条正文超过 4000 字的部分不参与检索（防一条长文拖慢整轮检索）；标题全文参与
- 停用插件后页面从主窗口左栏消失；重新启用即恢复，无任何副作用

## 实现说明（为什么搜得动）

依赖白名单只有 PyQt6 + 标准库，`jieba` / `whoosh` 这类库装进来也用不了（打包后 import 直接失败），所以中文检索这一整套是**从零写的**：

- **分词**：约 200 词的办公场景基础词表 + 双向最大匹配，择优取「词数更少、单字更少」的切法
- **检索项 = 词 ∪ 字符 bigram**，而且 bigram 在**整段**上生成（跨词）。好处有两个：词典外的自造词能召回；调换词序的两句话不再同分（`月报归档` 得到 `报归`，`归档月报` 得到 `档月`）。索引侧与查询侧走**同一个函数**，两边切法一致才可能搜得对
- **排序**：BM25（`k1=1.5` / `b=0.75`）。IDF 用 `ln(1 + 经典式)` 形式，保证恒 ≥ 0 —— 经典式在常见词（出现频率过半）上会变负，反而给「命中更多常见词」的文档扣分
- **停用词**只删「整项都是功能字」的项（`的 / 了 / 是`），`报 / 表 / 单` 这类既不删也不当停用字——删了会把「月报」的 bigram 一起毁掉

## 常见问题

- **搜不到刚写的内容？** 先切出去再切回本页（会重建索引），或直接点「🔄 重建索引」。
- **结果里没高亮？** 命中片段确实匹配、但高亮区间是「字面命中」才算；如果只是 bigram 交叉命中（查询词与原文用词不同但相邻字重合），会出现「这条命中了但片段里没有加粗」——正常现象，说明是按字符相关性召回的。
- **分数是什么意思？** BM25 相关度，只在本次查询内可比。绝对数值没有意义，用来判断「为什么这条排前面」。
- **能搜 ChatGPT 会话 / 插件数据吗？** 不能。只索引上面那四类宿主数据。
