# AI 助手 · 使用说明

`Ctrl+Alt+I` 或主窗口侧栏「🤖 AI 助手」进入页面（该插件是**页面插件**，
不占悬浮球右键菜单）。

## 首次配置

点输入行旁「⚙ 后端设置」展开设置卡，三选一：

**① 云端 / 常驻预设**——选预设后地址与模型名自动填入：

| 预设 | 地址 | 需要什么 |
|---|---|---|
| 云端 · DeepSeek | `https://api.deepseek.com/v1` | 在 api.deepseek.com 申请 API key |
| 云端 · 硅基流动 | `https://api.siliconflow.cn/v1` | 在 siliconflow.cn 申请 API key |
| 本地 · Ollama | `http://127.0.0.1:11434/v1` | 安装 Ollama 后 `ollama pull qwen3:4b` |
| 本地 · llama-server | `http://127.0.0.1:8080/v1` | 任何已启动的 llama.cpp 服务（含 CodeDrill 拉起的；若它要求认证会 401） |

**② 本地推理（推荐，零配置依赖）**——在「本地推理」区：

1. 「程序」点「浏览…」选 `llama-server.exe`（llama.cpp 发布包里有）
2. 「模型」点「浏览…」选 `.gguf` 模型文件
3. 端口默认 `8093`（避开 CodeDrill 的 8080 和 Ollama 的 11434）
4. 点「启动本地服务」→ 状态行显示启动进度，模型加载完自动接上

服务由插件拉起：退出 FloatPulse 时**自动结束**（内核级兜底），
不会留下占显存的孤儿进程。启动参数 `-ngl 99`（全量显卡卸载）。

**③ 保存并测试连接**——配置落盘并立即发一个探活请求，
状态行即时反馈：`✓ 连接成功` 或 `✗ 失败原因`。

## 输入与快捷指令

- 输入框 **Enter 直发，Shift+Enter 换行**
- **总结任务**：读全部任务（含截止日期、番茄计数），给优先级建议
- **整理碎片**：把随手记的碎片按主题归类，指出可转任务/笔记的项
- **本周小结**：任务 + 碎片 + 笔记一起总结成三段式小结
- **查知识库**：读知识库全部段落（带编号），先概括整体讲了什么，再指出最值得展开或最可能需要更新的编号
- 也可直接自由提问，支持多轮上下文（最近 12 条）

## 规则库（自定义 AI 行为）

点输入行旁「📐 规则库」展开规则卡，在这里写你希望 AI 长期遵守的偏好，
**规则完全由你自己编辑，插件不预置任何条目**：

- **＋ 添加规则**：新增一行；**🗑** 删除一行；文本框里按 **Enter** 直接保存
- 每条规则一行，**勾选＝生效**，取消勾选＝暂停（不必删除）
- **💾 保存规则**落盘到插件私有目录的 `config.json`，重启不丢
- 已启用的规则会在**每次对话**时追加到系统提示词末尾，云端与本地后端共用

示例规则：

- 回答保持简洁，不超过 200 字
- 周报类输出用 Markdown 表格
- 提到日期一律用「9月28日（周日）」格式
- 我的时区是 UTC+8，别用其他时区换算

## 把回复存成笔记

**在某条 AI 回复气泡上点右键** → 菜单里选「📥 存为笔记」，这条回复就存进
**笔记页**（标题自动取回复第一行，最长 40 字）。存过之后再右键，菜单项变为
「✅ 已存为笔记」并置灰，防止重复存。

入口放在右键菜单里而不是常驻按钮，是为了不占用对话区的视觉空间——每条回复
下方都挂一个按钮会让消息流显得很吵。

这是插件受限写能力（`ctx.write`）的用途——AI 整理出的东西可以直接落进
你的笔记，不用手动复制粘贴。**这个菜单项本身**是只增不改删的：它只能新建
笔记，不会修改或删除你已有的任何笔记。

## 让 AI 帮你操作数据（自然语言）

除了问答，你还可以**直接下指令**让 AI 改应用里的数据，例如：

- 「帮我把 3 号任务标记为已完成」
- 「新建一个任务：周五前交季度报表」
- 「把那条重复的碎片删掉」
- 「把周会记录这条笔记的标题改成『周会纪要』」
- 「记一条碎片：明天 10 点跟供应商对账」

**哪些会直接执行、哪些要先确认**（这是刻意的分级设计）：

| 类型 | 行为 |
|---|---|
| **新增**（任务 / 碎片 / 笔记） | **直接执行**，随后给一张结果卡列出做了什么 |
| **修改 / 完成 / 删除** | **先弹一张「⚠ 待确认」卡**列出将执行的操作（含目标记录标题），点「执行」才真正落库，点「取消」则数据零改动 |
| **删除成功后** | 结果卡上出现「↩ 撤销删除」按钮，点一下内容就能恢复 |

删除的撤销走「重新插入」路径，所以**恢复后的记录编号可能是新的**，但标题、
正文、完成状态都会原样还原。撤销按钮只能用一次，且宿主只保留最近 50 次
删除的快照。

几条能让你用得更顺的约定：

- **说清是哪一条**：模型只能操作数据里真实存在的编号，看不懂时会先反问你，
  不会自己猜着改。它在上下文里能看到带编号的任务/碎片/笔记列表
- **一次最多 10 个操作**：超出会被截断并提示
- **它做不到的事**：不会删除你的素材库文件、不会改设置、不会动 Obsidian 里
  的内容——改删能力被限制在任务 / 碎片 / 笔记三类数据
- **格式坏了就不做**：如果 AI 输出的动作格式不合法，插件会**整块放弃并如实
  告诉你「以下动作未被执行」**，绝不猜你的意思去改数据

写入与改删每次都会记一条 `[插件管理] …` 审计日志到 `float_data/app.log`，
你自己可以随时核对 AI 到底改了什么。

## 让 AI 操作知识库

知识库（`float_data/知识库.docx`）也在 AI 的操作范围里。它和任务/碎片/笔记
不一样——**用「编号」定位段落**，不是用不会变的 id。所以能这样说：

- 「把知识库第 4 段改写得更简短一些」
- 「往知识库里追加一条：客户投诉处理流程见附件 A」
- 「知识库里讲报价的那段过时了，删掉」
- 「查一下知识库，还有哪些段落是空的或者只有一句话」

| 类型 | 行为 |
|---|---|
| **追加新段落**（`add_knowledge`） | **直接执行**，结果卡告诉你落在哪个编号 |
| **改写 / 删除段落** | **先弹「⚠ 待确认」卡**（含段落原文片段与编号），点「执行」才落盘 |
| **删除成功后** | 结果卡带「↩ 撤销删除」，**放回原编号位置**（不是排到末尾） |

三个必须知道的规矩：

1. **编号会变**。删掉第 3 段，原来的第 5 段就变成第 4 段了。所以 AI 每次都是
   先读当前知识库、按**当时**的编号操作，你别拿着几分钟前的编号去下指令。
2. **内容对不上就不改**。AI 读取快照时会记住每段的「内容指纹」，执行前宿主会
   重新核对——这段时间里那段文字只要变过，操作就被**拒绝**（而不是改错段落）。
3. **你在 Word / WPS 里改过知识库时，AI 会拒绝写入**。因为落盘是整个文件回写，
   宿主怕覆盖你的手改内容。到**知识库页点一下「🔄 重新加载」**，让应用先同步
   你的改动，再让 AI 操作即可。

其它和前一条一样：编号必须是真实存在的、一次最多 10 个操作、格式坏了整块不
执行。另外，追加的段落**至少要 4 个字**（更短的段落会被知识库的过滤规则忽略，
等于白写）。

## 常见问题

- **HTTP 401**：key 缺失或无效。手动启动的服务若要求认证，关掉它的认证
  或改用上方「本地推理」自己拉起一个无认证服务
- **HTTP 404**：地址或模型名不对；llama-server 的地址应以 `…/v1` 结尾
- **连接拒绝**：端口上没有服务在听——本地服务还没启动，或端口号填错
- **超时**：本地模型首次加载较慢，重试一次即可
- **启动本地服务失败**：常见原因＝显存不足 / 端口被占 / gguf 损坏
- 数据只会在你点快捷指令或发送消息时才发给所选后端；所有请求只记
  URL 与耗时进 `float_data/app.log`，对话内容不落日志
