## 一、PyQt6 设置面板的三条铁律

### 1. 配置项"三件套"模式（沿用项目既有约定，验证有效）
新增配置项必须同时写三处，缺一不可：
- `DEFAULT_CONFIG`（默认值）
- `_CONFIG_TYPES`（类型校验，类型不符自动回退默认）
- `_CONFIG_RANGES`（数值范围，越界回退默认）

json 损坏/字段缺失/越界都能安全降级，UI 层永远拿不到非法值。

### 2. ⚠️ 批量刷新 UI 前必须 blockSignals（今天踩的真实 bug）
`refresh()` 里 `stepper.setValue(x)` 会触发 `valueChanged` → `_on_spin_changed`，
后者读取**其他还没同步的控件旧值**写回配置 → 批量刷新被部分回滚。
平时控件与配置同步所以无症状，一旦做"恢复默认设置"这类批量刷新就爆。

**修法（通用）**：
```python
for stepper, key, default in (...):
    stepper.blockSignals(True)
    stepper.setValue(config.get(key, default))
    stepper.blockSignals(False)
```
推广规则：**任何"程序主动改控件值"的代码，都要先问自己信号链会触发什么 handler**。

### 3. 重置默认 ≠ 全部重置
`reset_to_default()` 之后要回写"用户数据型"键，再广播全部联动信号：
- 保留键：软件导航条目(apps)、窗口几何、悬浮球位置、last_page_index —— 这些是用户录的数据，不是"设置"
- 广播：主题/球可见性/素材上限/动画速度/卡片尺寸/quick_capture_changed，漏一个就出现"设置页显示已重置但实际没生效"的分裂状态

## 二、Windows 原生能力（ctypes 零第三方依赖）

### 1. 取前台进程名（剪贴板过滤用）
```
GetForegroundWindow → GetWindowThreadProcessId →
OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION=0x1000) →
QueryFullProcessImageNameW → 取 basename、lower、去 .exe
```
要点：
- `PROCESS_QUERY_LIMITED_INFORMATION` **无需管理员权限**（比 PROCESS_QUERY_INFORMATION 宽松得多）
- 所有 API 失败都返回空串，过滤逻辑对空串放行——**查询失败绝不阻断主流程**
- 匹配时大小写/`.exe` 后缀双归一化，用户填 `wechat` 和 `WeChat.exe` 等价

### 2. 全局热键（RegisterHotKey + 原生事件过滤器，无额外线程）
- `RegisterHotKey(None, id, mods|MOD_NOREPEAT, vk)`：hwnd=None 时 WM_HOTKEY 投到线程消息队列，Qt 主循环泵出，**主线程注册即可**
- PyQt6 拦截方式：`QAbstractNativeEventFilter.nativeEventFilter`，判断 `eventType == b"windows_generic_MSG"`，用 `wintypes.MSG.from_address(int(message))` 解包
- 安装：`app.eventDispatcher().installNativeEventFilter(mgr)`
- **必须 MOD_NOREPEAT**（按住不重复触发）；至少强制一个修饰键，否则抢占普通按键
- 程序退出前 `unregister_all()`，否则组合键残留占用
- **意外收获：QT_QPA_PLATFORM=offscreen 下也能真实注册 Win32 全局热键** → 注册/注销逻辑可放心在离屏测试里验证

### 3. 小坑
- 光标位置是 `QCursor.pos()`，不是 `QGuiApplication.cursorPos()`（后者不存在）
- F1~F24 的 VK = 0x70 + n - 1；其他字符走 `VkKeyScanW`（高字节含 Shift 时应拒绝，避免解析歧义）

## 三、功能验证方法论（今天 4 轮全部采用，稳定有效）

分层验证链：`py_compile → pytest 既有用例 → offscreen 功能脚本 → GUI 冒烟`

功能级 offscreen 脚本的关键做法：
1. **临时目录数据，绝不碰真实 config.json/data**（test_init.py 曾因用真实配置把用户主题改回 light）
2. **弹窗组件用假类替换模块引用**：`import src.settings_panel as sp; sp.QMessageBox = FakeBox` —— PyQt 静态方法 monkeypatch 不可靠，替换模块命名空间引用才稳
3. **退出路径打桩**：`win._quit_app = lambda: quit_called.append(1)` 再调 `close()`，用记录数组断言分支走向
4. **FAIL 时先分清"代码错"还是"预期错"**：今天两次 FAIL 一次是预期错（DEFAULT_THEME 其实是 "dark"），一次是真 bug（信号级联）——先读常量定义再改代码

## 四、沙箱/工具链环境坑（本机复现过，跨项目可用）

| 坑 | 解法 |
|---|---|
| bash 管道里 `tail` 等 command not found，且会 **SIGTERM 中断整条命令** | 命令开头 `export PATH="/usr/bin:/bin:$PATH"` |
| PowerShell 工具不回传 stdout | 落盘到文件再用 python/Read 读 |
| GUI 程序无法脱离启动验证 | offscreen 模式跑组件级测试 + 用户实机验收交互效果 |
| 写入中文 Windows 文件必须显式 encoding="utf-8" | 项目内所有 json/py 固定 utf-8，json.dump 加 ensure_ascii=False |

## 五、功能设计决策记录（为什么这么做）

| 决策 | 理由 |
|---|---|
| close_to_tray 默认 True | 托盘图标常驻 = 永远有唤回路径，关闭即退出的"防僵尸"旧规则不再必要 |
| last_page_index 不记录说明页(8) | F1 说明页是临时页，恢复到说明页违背用户预期；范围校验 0-7 双保险 |
| 过滤判断放在读剪贴板文本**之前** | 被过滤的内容不更新去重缓存 `_last_text`，否则同内容换应用复制会被误吞 |
| 提醒气泡每类只列 5 条 | 气泡高度有限，标题加总数（"N 项待处理"），完整列表点气泡进任务页看 |
| 热键改错回滚不生效 | parse 失败恢复旧值并提示，避免用户输入 "K" 导致热键静默失效 |
| 恢复默认补发 quick_capture_changed | 热键/开关被重置后必须重注册，否则 UI 与实际行为脱节 |
