## 提示词

```text
【任务】
在 FloatPulse v4 的悬浮球上建立「动作注册表 + 外置插件」机制。
本轮为纯重构：不加任何用户可见功能，不改动球的现有交互语义。
完成后，新增一个专精功能应当只需往 plugins/ 放一个包，不需改 knowledge_ball.py。

【项目背景】
FloatPulse 是 Windows 桌面常驻悬浮球工具，PyQt6 原生实现。
- 开发主线：v4/（只有这里可以改）
- v2/ v3/：冻结的只读基线，禁止任何修改
- 运行数据在项目根 data/（7 个 json + app.log），各版本共用，勿改路径规则
- 路径定位走 v4/src/app_paths.py 的 get_base_dir()：
    打包运行(frozen) → exe 所在目录；源码运行 → 项目根目录
- 悬浮球主体在 v4/knowledge_ball.py（KnowledgeBall 类）
- 小卡片在 v4/src/card_window.py（CardWindow，6 个模式：
  fragment 碎片 / task 任务 / note 笔记 / nav 网址 / asset 素材 / app 软件）

【为什么要做这件事（不要偏离这个动机）】
悬浮球只有 7 条交互通道，且已全部占满：
  悬停=弹小卡片 / 单击=随机换卡 / 双击=打开主窗口 / 滚轮=顺序翻卡 /
  右键=菜单 / 拖放=文件分流(exe|lnk 进启动器，其余进素材或碎片) /
  热键=Ctrl+Alt+K 快速捕捉、Ctrl+Alt+S 截图钉屏、Ctrl+K 全局搜索
再往球里堆功能，只能靠右键菜单加层级、抢新热键、或改掉现有手势，三条都会毁掉「快」。
现有扩展点 KnowledgeBall.add_context_action(text, callback, separator_before=True)
已经开了个头（截图钉屏就是这么挂的），但它是「直接焊进球」，缺协议、缺入口分配、缺隔离。
本次要把它规范化为注册表 + 外置插件。

【已决策的边界（不要越界）】
- 核心内置，不插件化：球本体、CardWindow 六个模式、拖放分流、
  碎片/任务/笔记/网址/素材/软件。这些一律留在主程序里，不要外置。
- 可选功能外置：只有新增的「专精单一功能」走插件。
- 打包配置 FloatPulse.spec 不用改（plugins/ 在 exe 同级，运行时创建即可）。

【插件包形态（已决策，照此实现）】
- 分发格式：<id>.fpplug（本质就是 zip）
- 安装动作：把 .fpplug 解压到 <base_dir>/plugins/<id>/
- 运行时只加载文件夹，严禁用 zipimport 直接从压缩包导入
  （PyInstaller 打包后 zipimport 行为不确定，且插件内资源文件读取会踩坑）
- 若扫描到 plugins/ 下的 .fpplug 文件，自动解压到同名文件夹后再加载，解压后保留原文件
- 目录结构：
    plugins/color-picker/
      manifest.json    必需
      plugin.py        入口模块，必需
      icon.png         可选
- manifest.json 示例：
    {
      "id": "color-picker",
      "name": "屏幕取色",
      "version": "1.0.0",
      "entry": "plugin.py",
      "requires": [],
      "actions": [
        {"id": "pick", "title": "屏幕取色", "hotkey": "Ctrl+Alt+C", "menu": true}
      ]
    }
- 字段说明：id/name/version/entry 必需；requires 是依赖白名单声明；
  actions[].hotkey 可选、actions[].menu 为 true 时挂到右键菜单。
  缺失必需字段或 JSON 解析失败 → 跳过该插件并记日志，绝不能崩。

【依赖白名单（硬性）】
插件只允许依赖：PyQt6 + Python 标准库。
manifest 的 requires 里出现白名单之外的名字 → 拒绝加载，日志写明原因。
特别提醒：FloatPulse.spec 里 excludes 含 "ssl"，打包后插件做不了 https 请求，
不要写任何依赖网络的功能，也不要在插件里 import ssl / requests / urllib.request 做外网访问。

【要新建 / 改动的文件】
1. 新建 v4/src/plugin_api.py
   - PluginContext：插件能拿到的宿主能力，只暴露白名单方法
     （logger、show_toast、open_main_window、open_card_mode、config 只读快照）
   - BallAction（抽象基类）：id / title / run(ctx) / enabled()->bool
   - BallPlugin（抽象基类）：id / name / version / create_actions(ctx) -> list[BallAction]
   - ActionRegistry：register/unregister/get/trigger/all_actions/entry_conflicts
2. 新建 v4/src/plugin_loader.py
   - 扫描 <base_dir>/plugins/（目录不存在就创建，不报错）
   - .fpplug 自动解压；读 manifest；校验 requires 白名单；
     用 importlib.util.spec_from_file_location 从文件夹导入 entry 模块
   - 导入失败 / 类不符合协议 / create_actions 抛异常 → 单个插件跳过，
     记 logger.warning，绝不影响其他插件和主程序
3. v4/knowledge_ball.py 最小改动
   - 启动时调一次 PluginLoader 加载并把动作注册进 ActionRegistry
   - 右键菜单项、热键绑定改由注册表数据驱动（保留 add_context_action 作为兼容入口）
   - 不要重写鼠标事件逻辑，不要动 drag/drop/wheel/hover 的现有语义
4. 新建 v4/tests/test_plugin_api.py
   - 钉死铁律：构造一个临时插件目录 + manifest，加载后能在注册表里查到，
     且全程不 import knowledge_ball
   - 用例：缺字段跳过、依赖不合规跳过、插件 run 抛异常不影响其他插件、
     热键冲突时后者被跳过且日志有记录
5. 新建 v4/tools/verify_plugin_loader.py（离屏脚本，按现有 verify_* 脚本风格）

【不要做的事】
- 不要做依赖自动安装、在线插件市场、运行时热重载/卸载（禁用可以，真卸载不要）
- 不要用 QAbstractNativeEventFilter 自己注册热键：
  实测 Qt 会吞掉 hwnd==NULL 的线程消息，过滤器收不到。
  必须复用 v4/src/global_hotkey.py 里已有的独立线程 GlobalHotkeyManager。
- 不要把现有 6 个卡片模式外置成插件
- 不要改 v2/ v3/ 下任何文件
- 不要新增第三方依赖

【必须遵守的项目铁律（违反会导致后续重构成本剧增）】
1. 新增配置项必须「三件套」同步：src/config.py 的 DEFAULT_CONFIG + _CONFIG_TYPES
   （数值项再加 _CONFIG_RANGES）。不一致会被配置一致性护栏判红。
2. 主题颜色唯一真相源是 src/theme.py 的 THEMES 字典，新增颜色词 light/dark 两份都要加
   且要真正用上（QSS 用 Template.substitute 严格模式，缺键直接 KeyError）。
3. $primary 是浅色，其上文字必须用 $on_primary(#1B2B33)，严禁 white。
4. 按钮图标禁用 emoji，改全角符号（＋ U+FF0B、✎、⌗）。
5. 列表自定义行内容必须 QStyledItemDelegate 自绘，严禁 setItemWidget。
6. 子面板访问宿主只读属性，宿主侧必须写成 @property（否则拿到 bound method 静默回退默认值）。
7. 弹窗统一用 src/glass_dialog.py 的 GlassDialog + make_dialog_buttons。
8. 批量刷新控件前必须 blockSignals(True/False)。
9. 不要戳 main_window.py / card_window.py 的私有成员，需要能力就加公开方法或 property。
10. 本工程没有 git，可能多会话并行改同一文件（后写入覆盖先写入）：
    改动公共文件（knowledge_ball.py / theme.py / main_window.py / controls.py）前先看 mtime；
    替换代码按结构定位而非行号，并断言命中次数；改完立刻复跑全量测试。
11. 新增功能一律落在独立新文件里，尽量不碰 knowledge_ball.py —— 这正是本次重构的目的。

【离屏测试的已知坑（照做可省半天）】

【完成标准（逐条自查）】
```
