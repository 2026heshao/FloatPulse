## 1. 目标与边界

**目标**：全程序只保留**一个**文字搜索入口 —— Ctrl+K 直接打开 kb-search 插件页；旧
`GlobalSearchDialog` 的能力（素材、结果跳转）由插件承接。

**边界（重要）**：
- **不删除** `v4/src/global_search_dialog.py`。理由：插件可被停用 / 卸载 / 扫描失败，
  删掉旧对话框会让 Ctrl+K 变成死键。旧对话框**降级为兜底路径**，只在
  `show_plugin_page("plugin:kb-search")` 返回 False 时才打开。
- 插件仍保持 **`capabilities: []`（只读）**。「跳转」走 `ctx.parent_window()` 调宿主
  公开入口，与 `show_plugin_page` 同款约定，**不新增能力档位**、不动能力门禁。
- 素材只索引**文件名**（与旧对话框口径一致：`a.original_name`），不读文件内容。

## 4. 待用户拍板的细节

**跳转粒度**：`_on_search_jump` 目前**只对第 0 页（碎片）/ 第 2 页（笔记）真正带关键词定位**，
任务 / 素材只是切页，知识库连页都没有（旧对话框不覆盖知识库）。可选项：

| 选项 | 内容 | 代价 |
|---|---|---|
| **J1（最小）** | 复用 `_on_search_jump` 现状：碎片/笔记带关键词定位，其余只切页 | 0 |
| **J2** | 顺带把「知识库定位到第 N 段」也做掉（插件 uid 已带 `num`） | 需宿主知识库面板加定位入口，约 +1 轮 |
| **J3** | 任务 / 素材 / 知识库全部做到「定位到那一条」 | 三个面板各加定位入口，约 +2 轮 |

推荐 **J2**：知识库是本次并入的**主要新增覆盖**，不定位会显得「搜到了但找不到」；
任务/素材清单短，切页后肉眼可及，性价比低。
