## 二、P0 三条（你提的，逐条确认）

### 1. `recurring-tasks` 周期任务与例会提醒

**是什么**：一套时间规则引擎（每天 / 每周几 HH:MM / 每月几号 / 每 N 天），到期自动生成任务并主动提醒；含「每周五自动生成周报草稿并弹提示」。

**宿主现在**：任务只能手工建，周报插件要"想起来才点"。**这一条是唯一给 FloatPulse 补上"主动"二字的插件**。

**工程难点**：规则引擎要正确处理月末（31→28/30）、闰月；调度不能依赖一次性定时器（系统休眠不补偿、程序未启动会漏），得靠轮询比对 + 错过的补跑 + 生成记录去重。

**能力**：`write`（`add_task`）。**工作量**：~1 天。

---

### 2. `ai-text-workshop` 剪贴板 AI 文本工坊

**是什么**：热键唤起 → 自动带剪贴板文本 → 选动作（润色成正式邮件 / 翻译 / 总结要点 / 改语气 / 提取待办）→ 结果可复制、可存碎片、可存笔记。

**宿主现在**：AI 助手是"对话页"——长流程、有上下文、能操控应用内数据。它动不了**你正在别的软件里处理的文本**。这是**范式互补，不是重复**。

**工程难点**：本地 llama-server 进程生命周期管理（冷启动/复用/退出回收）+ 云端 OpenAI 兼容协议双后端统一；异步结果回 UI 线程；结果经 `write` 落回宿主数据链路后触发刷新。

**能力**：`network` + `write`。**工作量**：~2 天。

**前置依赖（宿主层决策，非本插件）**：后端配置目前在 `ai-assistant` 私有。若每个 AI 插件各配一套，用户要填两遍 key。需先定共享方案（见文末待拍板）。

---

### 3. `snippets` 快捷短语库

**是什么**：常用回复 / 地址 / 签名 / 会议开场白的短语库，热键 → 搜索 → 输出剪贴板。

**宿主现在**：临时素材和碎片解决的是"存进来"，**没有"取出去用"的通道**——短语库补的是这一侧，与碎片不重复。

**工程难点**：模板变量引擎（`{{date}}` `{{clipboard}}` `{{ask:提示}}` 等）与模糊搜索排序。变量引擎是它和普通 snippet 工具的分界线，也是这条插件的技术含量所在。

**能力**：无需特殊能力（可选 `write`，支持把碎片"升级"成短语——这条差异化只有 FloatPulse 能做）。**工作量**：~1 天。

---

## 三、P1/P2 三条（补充候选，同样是新功能）

### 4. `job-pipeline` 求职作战台

**是什么**：岗位卡片（公司 / 岗位 / JD / 投递日期 / 渠道）+ 阶段看板（待投 → 已投 → 笔试 → 面试 → offer / 挂）+ 拖拽流转 + 面试倒计时；AI 解析 JD 生成准备清单并批量落成任务。

**宿主现在**：任务是**平铺列表**，没有"一个实体在多个阶段间流转"的模型，也没有看板视图。

**工程难点**：Qt 拖拽看板（自定义视图 + drop 事件 + 数据落库）、阶段状态机（流转合法性校验）、AI 结构化输出解析与批量落地（结果要可核对，不能盲信模型）。

**为什么是 FloatPulse 能做**：JD 存在碎片池、准备项落成任务、面试进截止日分组、面经存笔记——**四份数据本来就在宿主里**，只是没有把它们串成一条流水线。

**能力**：`network` + `manage`。**工作量**：~3 天。

> 外部参照（真实需求已验证）：Teal / Huntr / Simplify / career-ops 是这个赛道的头部产品，核心卖点高度一致=「Kanban 看板 + JD 关键词匹配 + 阶段提醒」。开源侧 `Resume-Matcher`（~26.9k stars）支持本地 Ollama。说明需求真实且**本地化版本是稀缺位**（SaaS 都要把简历传上别人服务器）。

---

### 5. `kb-search` 本地知识检索

**是什么**：对知识库段落 / 笔记 / 碎片建**离线索引**，支持中文查询、按相关度排序、结果高亮并跳回原文。

**宿主现在**：知识库是顺序浏览 + 随机抽卡；全局搜索是字符串包含匹配，没有相关度概念，中文长句几乎搜不到东西。

**工程难点**：依赖白名单只有 stdlib + PyQt6，**不能用 numpy / jieba / faiss** —— 中文分词、倒排索引、BM25 打分、索引增量更新（mtime 指纹比对）全部要自己写。这是清单里技术含量最高的一条。

**为什么值得做**：你有 `D:\桌面\AI Port\my_kb` 知识库 + 越攒越多的碎片和笔记，但没有"问一句就找到"的入口。

**能力**：只读 + `data_dir`。**工作量**：~3 天。

---

### 6. `time-ledger` 时间账本

**是什么**：后台记录前台窗口归属，按天/周出「时间去哪了」分布图，并与番茄钟专注时长对照。

**宿主现在**：番茄钟是**主动**计时——只有你点了开始才算数。没计时的那 8 小时完全看不见。

**工程难点**：Win32 前台窗口低开销轮询、进程名→应用名归一、`GetLastInputInfo` 空闲检测、长时间跨度的数据聚合与可视化。

**能力**：只读（番茄钟快照）+ `data_dir`。**工作量**：~2 天。**优先级 P2**：价值取决于你是否在意时间统计。

## 7.2 两处必须修正的说法

**① `recurring-tasks` 不是「唯一补上主动二字的插件」**

宿主已有 `task_reminder_enabled`（`config.py:27`）= **启动时 + 每日 9:00 托盘气泡**提醒到期任务，
悬浮球也有徽标。所以「主动提醒」这个位已经有基础版，别对外宣称是独占。

真正的差距是**规则引擎**，差异化应改为：
- 宿主：**已知具体日期**的任务 → 到点提醒（一次性）
- 本插件：**只给规则**（每周五 15:00 / 每月 1 号 / 每 N 天）→ 自动生成实例 + 补齐错过的

**② `snippets` 与碎片的关系不是"不重复"而是"上层"**

碎片解决"存进来"（收集不可预知的输入），短语库解决"取出去用"（复用已成型的输出）。
两者是同一数据的两端，所以**「碎片右键 → 升级为短语」才是这条插件的独占点**——Raycast / Espresso / uTools 都做不了，因为它们没有碎片池。这条要写进插件说明。

## 7.3 顺带发现（不影响本次选题）

- 碎片右键有「存为笔记 / 加入知识库 / 加网址」，**唯独没有「转任务」**——这是宿主自身的小缺口，
  可先补内置（成本极低），或随 `job-pipeline` 一起补进插件。
- `kb-search` 只索引**宿主内数据**（知识库段落 / 笔记 / 碎片），**不碰文件系统** ——
  与「全局文件搜索交给 Everything」的红线不冲突，但外宣时必须写清是"站内检索"。
