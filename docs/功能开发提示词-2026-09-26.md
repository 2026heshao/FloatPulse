## 0. 公共约束（三份提示词共用，粘贴时请一并带上）

```text
【项目背景】
FloatPulse 是一个 Windows 桌面常驻悬浮球工具，PyQt6 原生实现（无 Electron）。
- 开发主线：v4/（只有这里可以改）
- v2/ v3/：冻结的只读基线，禁止任何修改

【技术栈】
Python 3.10+ / PyQt6 6.7+；除 PyQt6 与 python-docx 外，禁止引入任何第三方运行时依赖

【必须遵守的项目铁律（违反会导致后续重构成本剧增）】

11. 不要碰 main_window.py / card_window.py 这两个上帝类的内部结构；
```

## 1. 碎片自动分类 + 内容筛选

```text
【任务】
给碎片增加「内容语义分类」维度（第二筛选轴），让用户能从几百条碎片里按"这是什么东西"筛出
链接 / 代码 / 路径 / 命令行 / 普通文本。

【现状（已确认，请勿臆测）】
- v4/src/fragment_manager.py：
  Fragment 字段为 fragment_id/type/content/source/created_at；
  from_dict()/to_dict() 负责序列化；
  已有 type 四常量 TYPE_CLIPBOARD_TEXT / TYPE_CLIPBOARD_PATH / TYPE_FILE_PICKUP /
  TYPE_KNOWLEDGE_SEGMENT，以及 TYPE_LABELS / TYPE_ICONS 两个映射。
  已有方法：add_fragment / get_all_fragments / get_fragments_by_type / delete_fragment /
  delete_fragments / clear_by_type / count / count_by_type / trim_to_max / search_fragments。
- v4/src/fragments_panel.py：
  第 366 行已有 self._frag_filter（QComboBox）在筛 type，5 项：
  全部类型 / 剪贴板文本 / 剪贴板路径 / 文件拾取 / 知识段落，
  已接 currentIndexChanged -> refresh(preserve_view=False)；
  refresh() 第 520 行用 self._frag_filter.currentData() 取值；
  工具栏目前还有搜索框、预览开关、刷新按钮四个控件。
  列表项由 _MatchHighlightDelegate 自绘（内容左、时间右、命中高亮）。
  空状态由 _EmptyState 分 'empty' / 'no_result' 两态，且有一个「清空筛选条件」回调。

【关键前提】
现有的 type 是「来源渠道」（这条碎片是怎么进来的），本任务加的 category 是「内容语义」
（这条碎片是什么东西）。两个维度互不替代，不要合并，也不要改动 type 的既有语义。
例：一条从网页复制的 Python 代码，type=clipboard_text，category=code。

【实现要求】

1) 新建 v4/src/fragment_classifier.py（纯 Python，禁止 import PyQt6，便于直接跑 pytest）
   - 导出常量：CAT_TEXT / CAT_LINK / CAT_CODE / CAT_PATH / CAT_COMMAND
     取值建议 "text" / "link" / "code" / "path" / "command"
   - 导出 CATEGORY_LABELS（中文名映射）与 CATEGORY_ORDER（UI 下拉顺序）
   - 核心纯函数：classify(content: str) -> str
     判定优先级按此顺序短路，先命中先返回：
       a) link    —— 内容去空白后是一个独立 URL（http/https/ftp 协议或 www. 开头），
                     且不含换行与空格。注意：正文里「带一个链接的长段落」必须判为 text。
       b) path    —— Windows 盘符路径（^[A-Za-z]:[\\/]）、UNC（^\\\\）、
                     类 unix 绝对路径（^/ 且至少两段），整串只含路径本身。
       c) command —— 第一个 token 命中命令白名单
                     （pip/python/git/npm/node/curl/docker/gradle/mvn/conda/explorer/start/
                       cd/dir/copy/del/robocopy/net/sc/taskkill/winget/choco 等），
                     或整体命中 `xxx.exe <参数>` 形态。
       d) code    —— 满足以下任一：
                     · 多行且存在缩进行（行首 4 空格或 tab）
                     · 命中强代码特征：`def |class .*:|import |from .* import|#include|
                       public |private |function |=> |\(\) *{|; *$|</\w+>|SELECT .* FROM`
                     · 括号/分号密度超阈值（{ } ( ) [ ] = ; 合计占非空白字符比 > 4%）
       e) text    —— 兜底。空串、纯空白也一律返回 text（不许抛异常）
   - 分类函数必须对任意输入安全：None / 超长（>100KB）/ 含 emoji / 含控制字符都不许崩。
   - 若你发现某条规则边界与我描述冲突，以"宁可判成 text"为原则（误判为具体类别会让筛选漏内容）。

2) 数据层改造 v4/src/fragment_manager.py
   - Fragment 增加 category 字段，to_dict() 输出 "category"。
   - from_dict() 用 d.get("category") 取值；缺失或非法时调用 classify(content) 兜底，
     实现旧数据的自动迁移（老 fragments.json 里没有这个字段，不能读成空分类）。
   - FragmentManager 增加：
     · category_counts() -> dict  一次性遍历算全部类别计数（避免 UI 侧多次 O(n) 遍历）
     · get_fragments_by_category(cat) -> list
     · count_by_category(cat) -> int
     · set_category(fragment_id, cat) -> bool   手动改分类（右键菜单里会用），改完 mark_dirty()
   - 不要改 json 顶层结构（仍为 {"fragments":[...], "next_id":N}），只在元素内加字段。

3) UI 改造 v4/src/fragments_panel.py
   - 工具栏在 _frag_filter 之后新增 self._frag_category（QComboBox）：
     全部内容 / 链接 / 代码 / 路径 / 命令 / 普通文本（userData 存常量，"all" 表示不筛）。
   - refresh() 里先按 type 筛、再按 category 筛（AND 组合），最后再套搜索关键词。
     两个下拉的 currentIndexChanged 都要触发 refresh(preserve_view=False)。
   - 工具行已有 4 个控件，加第 5 个会挤。处理办法按优先级：
     a) 先把下拉项的文字缩短、下拉最小宽度调小；
     b) 仍放不下才允许把「预览 / 刷新」两个按钮改成图标按钮。
     但禁止改变标题行的栅格结构，禁止把工具栏换行成两排。
   - 列表项：在 _MatchHighlightDelegate.paint 里，于条目左侧画一条 3~4px 宽的类别色条
     （颜色从 get_colors() 取已有 token，如 primary / accent / warning / info 之类；
      若确实没有合适 token，才在 THEMES 的 light/dark 两份字典里同时新增）。
     日期分组行没有类别数据，保持原样不画色条。
   - _EmptyState 的 "no_result" 态文案需体现"筛选条件"是双轴的（类型 + 内容 + 搜索）。
   - 「清空筛选条件」按钮要把两个下拉都复位（注意 blockSignals）。

4) 刷新联调
   - 新碎片进来时 category 由 add_fragment 内部自动算（不要靠 UI 侧补算）。
   - 用户编辑碎片内容后（update_fragment），category 要跟着重算。

【验收标准】
A. pytest 新增 v4/tests/test_fragment_classifier.py，≥24 个用例，每条规则都要有正例与反例：
   - 普通中文句子 / 纯英文 / 空串 / 纯空白 / None -> text
   - https 链接、带 www 的链接、带 query 参数的链接 -> link
   - 「正文里提到 https://xxx 的一整段话」-> text（边界重点）
   - C:/Users/a.txt、D:\桌面\x.exe、\\\\server\\share、/usr/local/bin -> path
   - pip install PyQt6、git clone https://...、explorer.exe xxx -> command
   - 多行 Python 代码块、单行 def/class/import、JS 箭头函数、HTML 标签、SQL -> code
   - 只有数字的串 -> text
   - 超长 100KB 串不崩且 <50ms
   - 含 emoji / 控制字符不崩
   再补一组「旧数据迁移」用例：构造没有 category 字段的字典，
   Fragment.from_dict 后 category 非空且等于 classify(content)。
B. 三件套：若新增了配置项，DEFAULT_CONFIG / _CONFIG_TYPES 必须同步。
C. 离屏脚本 v4/tools/verify_fragment_category.py 断言：
   - 下拉存在且为 6 项
   - 混合数据下切到「代码」，列表条数 == FragmentManager.category_counts()["code"]
   - 计数标签文案与实际条数一致
   - 切回「全部内容」后条数恢复
   - 修复"空结果态"的清空按钮能把两个下拉同时复位
D. 四轮验证全过，pytest 不得新增 failed（基线 124 passed / 3 skipped）。

【不要做】
- 不要把 category 合并进现有的 type 字段。
- 不要引入 jieba / pypinyin / 任何分词与 NLP 依赖。
- 不要在 classifier 里 import PyQt6。
- 不要动 v2/ v3/，不要改 data/ 目录的路径规则。
```

## 2. 桌面便签多钉

```text
【任务】
允许把任意笔记 / 碎片同时钉成 N 个独立桌面便签浮窗（可拖动、可缩放、位置持久化、跟随主题），
关闭便签 = 取消钉住（不删数据）。

【现状（已确认，请勿臆测）】
- v4/src/note_manager.py：NoteManager 管 notes.json；
  Note 字段 note_id/content/create_time/update_time/title/title_auto；
  有 get_temp_note() 维护小卡片专用临时笔记；TEMP_NOTE_TITLE = "📌 临时笔记"，
  该条禁止删除（delete_note 会拒绝）。
- 现成可抄的浮窗：v4/src/screenshot_pin.py 的 PinWindow
  （Tool + FramelessWindowHint + WindowStaysOnTopHint、右键菜单、渐入动画、DPI 处理），
  以及 v4/src/card_window.py 的 CardWindow（右下角抓手等比例缩放、拖动偏移校准）。
- 悬浮球位置持久化先例：knowledge_ball.py 的 _schedule_position_save（600ms 防抖）
  + save_position_now（退出前兜底）。
- 弹窗统一 src/glass_dialog.py 的 GlassDialog + make_dialog_buttons。

【设计决策（已拍板，按此实现）】
便签的几何数据（位置/尺寸/透明度）存**独立的新文件** data/stickies.json，
不要塞进 notes.json，也不要给 Note 加 pinned 字段。
理由：几何信息与笔记内容生命周期不同（关窗口要丢几何、留笔记），
混在一个文件里会让"删笔记"变成跨文件级联操作，风险高。
stickies.json 结构建议：
  {"stickies": [{"sticky_id":1,"note_id":7,"x":..,"y":..,"w":..,"h":..,
                 "opacity":100,"always_on_top":true,"created_at":".."}], "next_id":2}
数据层同样走 src/json_store.py 的 load_records（records_key="stickies"），
特有后处理（见下）留在自己的 _load() 里。

【实现要求】

1) 新建 v4/src/sticky_notes.py
   - StickyStore：stickies.json 的增删改查。
     _load() 的后处理要做「孤儿清理」：note_id 在 NoteManager 里已不存在的记录直接丢弃，
     避免删了笔记后便签打开空白或报错。
     提供 upsert / remove / get_by_note_id / get_all / clear_all / count。
   - StickyNoteWindow(QWidget)：单个便签窗
     · FramelessWindowHint | Tool | WindowStaysOnTopHint
     · 顶部 26px 标题栏：显示笔记标题（太长省略）、拖动区、右侧关闭按钮
       （图标禁用 emoji，用 ✕ 这类全角/符号字符）
     · 主体 QTextEdit，编辑后 800ms 防抖自动保存（调用 note_manager.update_note），
       与主窗口笔记面板的保存节奏保持一致
     · 右下角抓手拖动缩放（复用 CardWindow 那套思路：delta=max(dx,dy)，别写死边长比例）
     · 右键菜单：标题重命名 / 置顶开关 / 透明度（三档或滑块——若用滑块必须是
       controls.Stepper）/ 删除并关闭 / 取消钉住
     · 窗口 flags 与 PinWindow 保持一致，避免任务栏出现图标、避免抢焦点
   - StickyNoteManager(QObject)：生命周期
     · open(note_id) / close(sticky_id) / close_all() / bring_all_to_front()
     · 数量上限 MAX_STICKIES = 20，超出时拒绝并给轻提示（不要静默失败）
     · 便签与同一条笔记一一对应，重复 open 同一 note_id 时复用并 raise + 激活
     · 位置/尺寸落盘沿用 600ms 防抖 + 退出时 save_now 兜底

2) 入口（三处，缺一不可）
   - 主窗口笔记面板：列表右键新增「📌 钉到桌面」
     （面板 _NotesPanel 里加，不要动 main_window 的结构）
   - 碎片工作台：右键菜单已有「存为笔记 / 加入知识库 / 添加至网址导航」三兄弟，
     在它们旁边补「📌 钉为便签」——这条会先转成笔记再打开便签，
     复用现有 _to_note() 的路径，不要复制一份。
   - 托盘右键菜单（knowledge_ball.py 里 _tray_menu 那一段）加「📌 便签」，
     弹子菜单列出当前已钉的便签 + 「全部关闭 / 全部置前」。

3) 主题与多屏
   - 主题切换跟随现有全局信号。**开工前先 grep 确认主窗口/右栏的主题广播信号名
     （如 theme_changed / apply_theme），不要臆造信号名**，确认不到就在 FloatingBall 同级
     加一个明确的公开信号并保持命名一致。
   - 多屏安全：创建位置若落在已拔掉的显示器坐标上，要夹回当前可用屏幕
     （参考 knowledge_ball.py 的 _ensure_ball_on_screen 与 get_screen_geometry 用法）。

【验收标准】
A. pytest 新增 v4/tests/test_sticky_store.py（纯逻辑，不依赖 GUI）：
   - 增删改查、note_id 唯一性、重复 open 返回同一 sticky_id
   - 孤儿清理：删掉笔记后对应 sticky 记录被清掉
   - 上限裁剪（>20 拒绝并有返回值表明原因）
   - stickies.json 损坏时走 json_store 的备份回退，不崩溃、不静默丢其他数据
   - 几何写入后读回一致（x/y/w/h/opacity）
B. 离屏脚本 v4/tools/verify_sticky_notes.py 断言：
   - 连开 3 个便签，三个 geometry 均在可用屏幕范围内且互不重叠
   - 拖动 / 缩放后 600ms 防抖到期，stickies.json 里的几何已更新
   - close 后再 open，位置尺寸还原
   - 便签数量在≥上限时给出提示而非新增窗口
   - 主题切换后标题栏背景色确实改变（取像素比色，别靠 QSS 字符串）
C. 四轮验证全过。

【已知限制，必须在总结里如实说明】
离屏环境无法验证输入法与窗口焦点行为（Tool 窗里的中文输入法、失焦自动保存、
跨屏拖拽）需要在用户真机上补测，不能声称"已验证"。

【不要做】
- 不要给 Note / notes.json 加字段，不要改 NoteManager 既有方法签名。
- 不要新开 config 项来描述便签内容数据（只有几何才进 stickies.json）。
- 不要让便签抢焦点（不要用 raise_() 之外的方式打断用户当前输入窗口）。
```
