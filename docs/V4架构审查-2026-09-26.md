# V4 架构审查报告（2026-09-26）

> 审查范围：`v4/` 全量（约 18850 行源码 + 1400 行测试）。
> 结论先行：**当前架构可以继续加功能，成熟度在单人项目里属上游**；
> 但两处结构性债务会在做「命令面板」这类跨面板大功能时显著放大成本，
> 建议在那之前完成 P1 清理。

---

## 一、做对了的（保持，不要动）

| 项 | 证据 |
|---|---|
| 三层解耦（UI/业务/数据） | 面板不直接读数据文件，统一走 manager；`json_store` 五管理器共用加载 + 各自后处理 |
| 不变量有测试护栏 | 主题对比度、host 属性契约、导航拖拽、json 骨架均有钉死测试（124 passed） |
| 主题单一真相源 | 颜色只进 `THEMES` 字典，QSS 模板严格替换（缺键 KeyError 兜底） |
| 离屏验证工具链 | `tools/run_gui_check.py` subprocess+timeout，GUI 回归可脚本化 |
| 配置三件套一致性 | DEFAULT_CONFIG / _CONFIG_TYPES / _CONFIG_RANGES 同步，有护栏测试 |
| 健壮性底座 | 原子写入、损坏回退、单实例互斥量、全局异常钩子、多屏漂移兜底 |

## 二、债务清单（按风险排序）

### D1 `knowledge_ball.py`（2250 行）—— 上帝入口
- main() 内 44 处 signal connect、27 个模块 import
- FloatingBall 类、托盘、任务提醒调度、快捕条/截图钉屏接线、安全退出全在一个文件
- **症状**：每次加全局功能都要在 main() 里再接一段线，`_safe_quit` 已经开始"穿越"引用后定义的变量
- **处方**：拆 `src/wiring.py`（信号接线）+ `src/tray.py`（托盘+提醒）；main() 只留组装

### D2 两个上帝类
- `main_window.py` 2078 行 / 112 方法；`card_window.py` 1906 行 / 89 方法
- 面板本身已拆独立文件，但容器仍承担调度/刷新/几何/转场多重职责
- **处方**：按页拆 mixin（`_refresh_xxx` 家族独立），或至少把"页面刷新调度"抽成 RefreshDispatcher

### D3 私有属性穿透（8 处）
- main() 里 `ball._card_window._last_mode`、`._switch_mode()`、`._refresh_task_list()` 等直接戳私有成员
- **症状**：重构 card_window 内部随时炸 main()，且无编译期提示
- **处方**：升公开 API——`CardWindow.refresh_page(kind)` / `reset_to_home()` / `current_mode` property，并用 `test_host_attribute_contract` 同款测试钉死

### D4 热键注册逻辑重复（本次修复新增的教训）
- 快捕条与截图钉屏各自 `_apply_xxx_hotkey()` + 独立 GlobalHotkeyManager
- 独立实例是对的（避免 unregister_all 互踢），但"读配置→注销→重注册"样板会随热键数量翻倍
- **处方**：第三个热键出现时抽 `HotkeyBinding(mgr, config_key, default, callback)`；两个时不动

### D5 测试盲区
- `clipboard_monitor`（20MB 上限/最小边/sha256 去重闸门）无专测
- `screenshot_pin` 有离屏脚本（22 断言）但无 pytest 层
- **处方**：manager 层补 pytest（纯逻辑、不依赖 GUI）；截图模块保持离屏脚本即可

### D6 低优先
- `theme.py` 1227 行三份 QSS Template → 可拆 `qss/` 目录按窗口分文件
- `data_changed(kind)` 字符串分发 → 收敛为常量/枚举（现量小，先不动）

## 三、建议节奏

1. **现在**：无需重构，继续按功能推进（间隔重复、命令面板可直接开工）
2. **命令面板开工前**：完成 D1（拆 wiring）+ D3（公开 API），约半天——这两项不做，命令面板会在 main() 里再堆 20+ connect
3. **命令面板之后**：D2 拆容器类，D5 补 manager 测试

## 附：本次顺手修复

- **截图热键无效根因**：`GlobalHotkeyManager` 的 id 计数器是实例级的，而 `RegisterHotKey(hwnd=NULL)` 的 id 空间是线程级——快捕条和截图两个实例都从 id=1 注册，实测同 id 重复注册返回 True（顶替旧注册），`WM_HOTKEY` 按 id 路由时两实例互相串台。已改为类级递增计数器，并新增 `tests/test_global_hotkey.py` 钉死多实例 id 不相交。
- **注意**：修复需重启程序生效；审查时发现本机有正在运行的旧 v4 实例（Ctrl+Alt+K 已被其占用），旧实例热键状态不可信。
