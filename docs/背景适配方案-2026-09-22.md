# 背景适配问题与三条修改路线

> 日期：2026-09-22
> 触发问题：你截图里看到的现象 —— 玻璃窗口浮在终端 / 聊天窗口 / 桌面上时，**背后内容原样透传**，和前景文字叠成两层，读起来是糊的。

---

## 一、根因

HTML 效果图里的玻璃靠 `backdrop-filter: blur(26px)` —— **浏览器会真的把背后内容模糊掉**。
Qt 自绘只能做「半透明叠加」，做不到模糊，于是：

| 层 | HTML 高仿真 | v2 实机 |
|---|---|---|
| 背景 | 被模糊成柔和色块 | **原样透出**（文字、线条全在） |
| 前景 | 卡片文字 | 卡片文字 |
| 结果 | 清晰 + 通透 | **两层文字打架，糊** |

所以问题不在颜色，也不在圆角 —— **缺的是"模糊"这一层。**

---

## 二、四种方案的实测对比

`设计稿/验证-背景适配-对比.png`（我把你屏幕上真实的背景抓下来，在同一块背景上叠了四种方案）：

| 方案 | 做法 | 观感 |
|---|---|---|
| **A 现状** | 半透明 67%，背景原样透出 | ❌ 背景文字与前景叠加，糊 |
| **B 保底** | 不透明 80~88%，几乎看不到背景 | ✅ 清晰；❌ 基本没有玻璃感 |
| **C 模糊底 + 67%** | 抓取卡片**背后那块的背景 → 模糊 → 当底图**，再叠 67% 填充 | ✅✅ 背景糊成柔和色块，文字清晰，**通透感也保住了 → 最接近设计稿** |
| **D 模糊底 + 88%** | 同上，但填充更实 | ✅ 很干净，比 C 更"实"，透明感弱一些 |

结论：**只要补上"模糊"这一层，可读性和质感可以同时拿到。**

---

## 三、三条可行的技术路线

### 路线 1：保底 —— 提高不透明度（零风险）

- 把玻璃填充从 67% 提到 **80~88%**
- 优点：改一个数字，零依赖、零性能开销、零副作用
- 缺点：玻璃感明显减弱（变成"磨砂实色卡"）
- 适用：只想快速把可读性问题按下去

### 路线 2：自绘模糊底（推荐主线，效果 = 对比图 C/D）

- 做法：窗口显示 / 移动结束后，用 `QScreen.grabWindow` 抓取**窗口所在屏幕区域** →
  降采样到 1/12 再放大（廉价近似高斯模糊，耗时几十微秒）→ 作为窗口最底层绘制
- 关键技术点：必须调 `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)`
  让**自己的窗口不被抓屏捕获**，否则会把自己糊进背景里（递归残影）。
  该 API 在 Win10 2004+ 可用，失败时降级为路线 1
- 成本：窗口移动/背景变化时重抓（例如停下 300ms 后抓一次）；拖拽过程中用旧底图，不卡
- 副作用：① 程序会读取屏幕像素（**只在内存里用于本窗口背景，不落盘、不外传**）；
  ② 开了 EXCLUDEFROMCAPTURE 后，录屏/共享屏幕时该窗口对录制端不可见
- 优点：效果确定、可控、不依赖系统版本；卡片仍能保住 22px 大圆角
- 缺点：需要抓屏；背景快速变化时（视频/滚动）底图会短暂滞后

### 路线 3：系统亚克力 / 云母（最省资源，但需实测）

- 做法：调 Windows DWM 让**系统合成器真实模糊**窗口背后 —— 不用抓屏、CPU 几乎零开销
- 本机 API 已验证（我在沙箱跑过）：
  - `DwmSetWindowAttribute(38, 3)`（Win11 亚克力）→ 返回 **0（成功）**
  - `SetWindowCompositionAttribute(state=4)` → 返回 **1（成功）**
  - 系统圆角 `(33)` → 返回 **0（成功）**
- **但 API 成功 ≠ 视觉生效**：Qt 窗口为了圆角/自绘阴影用了 `WA_TranslucentBackground`
  （即分层窗口），而系统材质恰恰要求**非分层窗口** —— 这是已知冲突。
  沙箱里无法验证真实合成效果，需要你在本机看一眼
- 已给你准备好实测工具：**双击 `启动v2.bat demo`** → 弹出三张可拖动的卡片
  （A 现状 / B 不透明 / C 亚克力），把它们拖到深色代码、白色网页、图片上对比即可
- 若 C 卡片真的模糊了 → 走这条路线最省资源；若仍只是普通半透明 → 说明冲突未解，用路线 2

---

## 四、我的建议

1. **先跑一次 `启动v2.bat demo`**（10 秒看一眼），确认系统亚克力在你机器上到底生不生效；
2. 无论结果如何，**路线 2（自绘模糊底）都值得做**：它是唯一"效果确定、可控、且能保住卡片 22px 圆角"的方案，也最接近你已确认的设计稿；
3. 路线 1 只作为降级兜底（例如用户在设置里关掉模糊时）。

---

## 五、需要拍板的问题（原始清单）

1. 是否接受**路线 2 的抓屏行为**（仅本窗口背景用、不落盘、不外传，但程序确实会读屏幕像素）？
2. 若接受：模糊底 + **67%**（更通透，同对比图 C）还是 **80%**（更稳，同对比图 D）？
3. 模糊要不要做成**设置页开关**（性能敏感或录屏时一键关掉，退回路线 1）？

---

## 六、实际决定与调整记录（2026-09-22 下午）

**实机反馈**：用户跑起来后发现，在"背后是多窗口文字界面"的真实场景下，67% 的填充让背景文字
直接透上来与前景打架，读起来很累（比对比图里的纯色块背景严重得多）。

**决定**：先走**路线 1（保底）**，把实度提上去；模糊方案暂缓。

**改动**（`v2/src/theme.py`）：

| 主题 | 项 | 改前 | 改后 |
|---|---|---|---|
| 浅色 | `glass_fill` | 67%（172） | **88%（224）** |
| 浅色 | `panel_fill` | 55%（140） | **67%（170）** |
| 浅色 | `glass_highlight` | 50%（128） | 55%（140） |
| 深色 | `glass_fill` | 69%（176） | 82%（208） |
| 深色 | `panel_fill` | 8%（20） | 10%（26） |

**验证**（`v2/demo_bg_preview.py`：抓真实屏幕背景 + 内存合成四档不透明度）：

- 旧 67% → 背景文字明显透上来，与卡片文字打架
- **88%（当前值）→ 背景几乎看不见，卡片文字清晰，仍能透出一点底色**
- 92% / 96% → 更干净，但已接近实色

结论：**88% 是"可读性"与"玻璃感"的当前平衡点。**
代价是通透感明显减弱 —— 这正是保底方案的固有取舍；
若将来想同时拿到"通透 + 干净"，仍需回到模糊路线（系统亚克力或抓屏模糊）。

**后续可选项**：
- 把实度做成设置页滑块（用户按自己壁纸/使用习惯微调），一次改动即可覆盖所有偏好；
- 或做"一次性背景亮度采样"：窗口显示时采一次，决定用深字还是浅字、玻璃偏白还是偏黑（零抖动）。
