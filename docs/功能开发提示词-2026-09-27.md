## 1. Obsidian Markdown 导出

```text
【任务】
把 FloatPulse 里的笔记、碎片、任务单向导出成 Obsidian vault 可用的 Markdown 文件，
让用户在 Obsidian 里能继续编辑、检索、链接这些数据。

【产品定位（务必理解，决定了所有取舍）】
FloatPulse 是「办公便捷功能集合体」，不是学习工具、不是知识复习工具。
导出功能的目的是**打破数据孤岛**：用户在浮球里随手写的东西，
不应该被锁死在只有 FloatPulse 能读的 json 里。
为此可以牺牲一切花哨的东西。不要引入任何"复习""记忆曲线""卡片"相关的概念或算法。

【现状（已核对，请勿臆测）】
- v4/src/note_manager.py
  Note 字段：note_id / content / create_time("YYYY-MM-DD HH:MM") /
             update_time / title / title_auto(标题是否由内容自动生成)
  to_dict() 键：note_id, title, title_auto, content, create_time, update_time
  注意 TEMP_NOTE_TITLE = "📌 临时笔记" 是系统保留笔记，delete_note 会拒绝删它。
  导出时建议跳过它（它是写了一半的草稿，不是用户的正式笔记）。
- v4/src/fragment_manager.py
  Fragment 字段：fragment_id / type / content / source / created_at / category
  type 是来源渠道（TYPE_CLIPBOARD_TEXT / TYPE_CLIPBOARD_PATH / TYPE_FILE_PICKUP /
      TYPE_KNOWLEDGE_SEGMENT），category 是内容语义
      （CAT_LINK / CAT_CODE / CAT_PATH / CAT_COMMAND / CAT_TEXT，见 fragment_classifier.py）
  这两个维度都存在，导出时要都体现，不要只写一个。
- v4/src/task_manager.py
  Task 字段：task_id / title / note(备注) / deadline("YYYY-MM-DD") / done /
             created_at / completed_at / focus_sessions
  任务是流动状态（今天没做完明天做），不适合每任务一个文件。
- 路径 API 一律走 v4/src/app_paths.py：get_project_root() / get_base_dir() /
  get_data_dir() / get_temp_assets_dir() / get_docx_path()。
  严禁自己拼 join(base, "data")，也不要假设工作目录是项目根（打包后不是）。
- 文件选择对话框先例见 v4/src/assets_panel.py 第 376 行（另存为）与
  v4/src/screenshot_pin.py 第 650 行（保存截图），照它们的写法。
- 设置页六分组结构见 v4/src/settings_panel.py：`group = self._group_card` 别名，
  调用形如 `gv = group(v, "⚡ 全局工具")`，行用 `_add_row(gv, 标题, 说明, 控件, ...)`。
  开工前先读第 51 行 _group_card 与第 135 行附近的分组列表，**照现有样式加第七组或
  并入现有组，自选但要在总结里说明理由**。

【设计决策（已拍板，按此实现）】
A. **单向导出，绝不做双向同步**。
   FloatPulse 写 md，Obsidian 读 md。不做反向读取、不做冲突检测、不做定时自动导出。
   理由：双向同步是另一个量级的工程（需要 mtime/stamp 比对、删除传播、冲突 UI），
   一旦开了头，后续所有数据安全问题都会找上来。本轮只做「一键导出 + 重复导出可覆盖」。
B. **vault 路径可配置，不硬编码**。
   存进 config 的 obsidian_vault_path（字符串，默认空串）。
   空串 = 用户还没选过，导出时弹 QFileDialog.getExistingDirectory 让用户选，
   选完记住。用户本机参考 vault 路径是 D:\桌面\AI Port\my_kb，
   **但绝不能写成默认值或推荐值**，只能作为你本地测试时的输入。
C. **导出根目录下固定子目录** `FloatPulse/`（即在 vault 下建 FloatPulse 文件夹，
   里面再分笔记 / 碎片 / 任务）。避免污染用户 vault 根目录。
D. **幂等**：同一个内容重复导出必须产生同一个文件、同样的内容，
   不允许第二次导出变成追加副本或加时间戳副本。
   用户改了笔记再导出，同一个 md 应该更新而不是新建。

【实现要求】

1) 新建 v4/src/md_export.py（Markdown 生成部分必须是纯 Python，禁止 import PyQt6）
   - Windows 文件名安全化函数 safe_filename(name, maxlen=60)：
     非法字符 \ / : * ? " < > | 以及控制字符、首尾空格与末尾点一律处理；
     结果为空时返回兜底名（如 "untitled"）；超长截断。
     这是安全敏感点，重复导出时它必须稳定（同名输入永远得同名输出）。
   - frontmatter 生成：YAML 三横线块，键建议
       created / updated / tags: [FloatPulse] / source: <来源> / category: <类别>
     tags 用 Obsidian 的 YAML 列表语法，不要写成字符串。
     **内容里若本身以 `---` 开头，必须做转义处理**（否则 frontmatter 会被破坏），
     处理方式自选但要有测试覆盖。
   - 三个渲染器，各自一个函数：
     · render_note(note) -> (filename, markdown)
        每篇笔记一个 md。正文直接放笔记内容。
     · render_fragment_day(date_str, fragments) -> (filename, markdown)
        碎片按天汇总成 碎片/YYYY-MM-DD.md，当天每条用一个二级标题或列表项区分，
        必须带上 时间 / 来源 type / 内容类别 category。
        按天聚合而非每条碎片一个文件 —— 几百条碎片产生几百个 md 是灾难。
     · render_tasks(tasks) -> (filename, markdown)
        任务汇总成一个 任务汇总.md，用表格或分组列表表达
        （建议按是否完成分组，未完成在前）；带 deadline 与 focus_sessions。
   - 一个统一的导出编排函数：
     export_all(vault_dir, notes, fragments, tasks, opts) -> ExportResult
     ExportResult 至少含：files_written(list[str]) / skipped(list) /
     errors(list[tuple[str,str]]) / total_ms
     任何单条记录渲染失败都要进 errors 并**继续处理下一条**，不许中途抛出中断整批。

2) 配置项（必须同步三件套 DEFAULT_CONFIG / _CONFIG_TYPES）：
     obsidian_vault_path   str   默认 ""      vault 根目录（空=未选择）
     export_notes          bool  默认 True
     export_fragments      bool  默认 True
     export_tasks          bool  默认 True
   bool 不进 _CONFIG_RANGES（这是项目的既定规则，别多写）。

3) 入口（至少两处，都做成最简单的一行菜单/按钮）
   - 设置页：新增导出操作行（一个「导出到 Obsidian」按钮 + 当前 vault 路径显示 +
     「更改目录」），点击执行导出，完成后用现有 show_toast 给轻提示，
     提示里要带「共 N 个文件」，失败要明确说失败几条。
   - 主窗口三个面板（笔记 / 碎片 / 任务）的右键菜单各加一个导出项。
     **不要在三个地方复制三份导出逻辑**，统一调到 md_export 或宿主暴露的公开方法。
     主窗口 main_window.py 与面板是上帝类/上帝入口，不要改它们内部结构，
     需要的能力请在上面加公开方法。

4) 健壮性（这些是必须处理的，不是"建议"）
   - vault 路径不存在 / 不是目录 / 无写权限：给出明确失败原因，不要静默、不要崩。
   - 导出过程中同名的 md 已被用户手动改过：本任务是"单向导出"，
     按既定语义**覆盖**即可，但要在这次导出的结果里告知用户覆盖了哪些文件。
   - 超大碎片（>100KB）正常写入，不要截断（除非你明确决定截断并在总结里说明）。
   - 编码强制 utf-8，Windows 下不要依赖系统默认编码：
     一律 open(path, "w", encoding="utf-8", newline="\n")。
     newline 必须显式指定，否则 Windows 下换行会被写成 \r\n，
     Obsidian 里部分插件会把 \r 显示成异常符号。

【验收标准】
A. pytest 新增 v4/tests/test_md_export.py，≥20 个用例：
   - safe_filename：含全部 9 个非法字符 / 纯空格 / 纯 "." / 超长 300 字 /
     中文标题 / 空串 -> 结果均合法且稳定（同输入两次结果一致）
   - frontmatter：内容体以 `---` 开头时不破坏 YAML 块
   - render_note / render_fragment_day / render_tasks 各自的输出结构
     （碎片必须能查到 category 与 type；任务必须能查到 deadline）
   - export_all 的编排：某条渲染抛异常时其它条仍被导出、异常进 errors
   - 幂等：同一输入导出两次，files_written 完全相同、文件内容逐字节相同
   - 编码：写出的文件用 utf-8 读回，换行符是单个 \n 而不是 \r\n
   - 空数据：notes/fragments/tasks 全空时不报错，产出 0 个文件并给出合理结果对象
B. 离屏脚本 v4/tools/verify_md_export.py 断言：
   - 导出到临时目录后，笔记/碎片/任务的目录与文件名符合预期布局
   - 设置页导出按钮存在且点击不崩
   - vault 指向一个文件时给出错误提示而非崩溃
   - 取消目录选择（QFileDialog 返回空）时不导出、不报错
C. 四轮验证全过，pytest 不得新增 failed。

【已知限制，必须在总结里如实说明】
本任务无法验证真实 Obsidian 客户端的渲染结果（本机未安装 Obsidian，
且项目禁止引入第三方运行时依赖去做 md lint）。
frontmatter 语法与 wikilink 兼容性只能靠人工校对，不能声称"已验证 Obsidian 可用"。

【不要做】
- 不要做双向同步 / 定时自动导出 / 增量 diff。
- 不要引入任何第三方依赖（yaml 库也不许，frontmatter 手写字符串拼接即可）。
- 不要在 md_export.py 里 import PyQt6（逻辑层要与 GUI 解耦，便于 pytest）。
- 不要删改用户原有的 json 数据，导出是只读操作。
- 不要把 TEMP_NOTE 临时笔记导出（除非你明确决定导出并在总结里说明）。
- 不要碰 v2/ v3/，不要改 data（float_data）目录路径规则。
```
