# 插件选题推荐（2026-09-28）

面向 FloatPulse「办公便捷功能集合体」定位，基于全网同类工具插件生态调研，筛出**值得自己开发**的插件。
现有插件：`weekly-report`（周报）、`ai-assistant`（AI 助手，含联网/页面/动作协议）。

---

## 一、调研来源与可信度

| 来源 | 关键事实 | 可信度 |
|---|---|---|
| Raycast 官方商店 / 2026 评测 | Snippets（常用语）是**内置核心能力**而非商店扩展；Clipboard History 被作者列为"不用就在损失生产力" | 一手 |
| Raycast 扩展榜（第三方博客） | 高频上榜：GitHub / Linear / Notion / Color Picker / Kill Process / System Monitor / Snippets | 二手，趋势可参考 |
| uTools 插件专题「必备」「高效办公」 | 必备榜首三位：本地搜索、剪贴板、OCR；紧跟 备忘快贴、聚合翻译、PDF 处理、ToDo 待办 | 一手（官网专题页） |
| uTools「超级待办」插件描述 | 卖点明确写"AI 帮你写周报、写日报、写总结" | 一手 |
| Obsidian 插件下载量（obsidianstats.com） | Top10：Excalidraw / Templater / Dataview / Tasks / Advanced Tables / Calendar / Git / Kanban | 一手 |
| Flow Launcher 插件推荐 | 常装六件：Clipboard+、Window Walker、Steam Search、Colors、Emoji+、Spotify | 二手 |
| 待办工具横评（多篇自媒体） | "职场人日均 12–25 项碎片任务，68% 因遗漏/混乱降低效率"；重复任务（周会、月报）是刚需 | **【待核实】**——各家都引"2026 行业调研"但无原始出处，只作方向参考 |

**从调研里读出的三条规律：**

1. **高频 ≠ 高价值**：取色、翻译、OCR、emoji、进程管理在各家榜单都很热，但它们是**通用工具**，谁做都行，且与 FloatPulse 主线（记完之后）无关。
2. **真正稀缺的是「沉淀层」**：Snippets、剪贴板历史、待办/周期任务、日报周报 —— 这些才是"收集完之后怎么用"的位置，正是 FloatPulse 的定位空档。
3. **重复/周期任务是明确缺口**：多篇待办横评都把"每周例会、每月总结设一次重复规则"当核心卖点，而 FloatPulse 的任务模块目前**没有重复能力**。

---

## 二、选型判据（四条，缺一不推荐）

1. **贴合四大场景**：随手记 / 临时存 / 找东西 / 盯截止日 / 对照参考。
2. **吃宿主独占数据**：碎片池、双轴分类、任务、笔记、番茄钟快照 —— 外部工具拿不到，才轮到 FloatPulse 做。
3. **不是别人的优势区**：翻译 / OCR / 取色 / 文件搜索 / 窗口管理 / 进程管理一律排除。
4. **成本可控**：PyQt6 + stdlib，不引第三方库，单插件 0.5–2 天。

|---|---|---|---|---|---|

## 四、逐个说明

### P0-1 `snippets` 常用语速插

**做什么**：热键（`Ctrl+Alt+;`）唤出搜索框，模糊匹配片段名 → 回车 → 内容写进剪贴板并**自动粘贴到当前光标位置**。附带"把当前选中文本存为新片段"。

**为什么是它**：Raycast 把 Snippets 做成内置核心功能、uTools 有「备忘快贴」「超级文本片段」两个同类插件且都进必备榜 —— 这是被三个生态同时验证过的最高频需求。FloatPulse 的优势是球常驻桌面，唤起路径比开 uTools 更短。

**实现要点**：
- 片段库存 `ctx.data_dir/snippets.json`，写文件走**临时文件 + `os.replace`** 原子落盘（与宿主数据层同风格）。
- 热键路径 `run()` 跑在**原生事件过滤器**里 → 开对话框必须 `QTimer.singleShot(0, ...)`，否则重入崩。
- 弹窗继承 `src/plugin_ui.PluginDialog`（裸 QDialog 会退化成系统外观）。
- 粘贴：`ctypes`（stdlib，白名单内）调 `user32` 发 `Ctrl+V`。**坑**：Qt 窗口弹出会抢焦点 → 先在 `run()` 里 `GetForegroundWindow()` 记下原窗口句柄，写剪贴板后 `SetForegroundWindow` 回来再发按键。
- 可选声明 `write`：让用户把碎片池里的常用内容一键"升级"成片段，形成 碎片→片段 的反向闭环。

**验收**：在记事本/浏览器输入框分别测试，粘贴成功且不丢焦点；片段库损坏时降级为空列表不崩。

---

### P0-2 `inbox-triage` 碎片收件箱清理

**做什么**：定时扫描碎片池，把**超过 N 天未处理**的碎片挑出来，悬浮球角标提示；点开是页面插件，逐条给三个按钮：转任务 / 转笔记 / 删除，支持批量"全部忽略"。

**为什么是它**：碎片池是 FloatPulse 自己造出来的数据结构，**堆积问题只能自己解** —— 外部工具碰不到这些数据。这是最"独占"的一个插件，也是唯一能把闭环从"收集"补到"消化"的那一环。

**实现要点**：
- 需要 `capabilities: ["write", "manage"]`（转任务/笔记用 `add_*`，删除与标记用 `delete_*` / `update_fragment`）。
- `delete_*` 返回**撤销令牌** → 面板上必须给「↩ 撤销」按钮，调 `undo_delete(token)`（一令牌一用，编号可能变新，是预期行为）。
- 页面插件：`manifest "page"` + `create_page(ctx)` → `register_plugin_page()`（索引 10+，不占 `last_page_index`）。
- 老化判定只看碎片 `created_at` + 本地"已处理"标记（`data_dir/handled.json`），**不改动宿主碎片结构**。
- 定时器在 `on_disable` 里停掉（钩子异常由 loader 隔离，但仍要自己收尾）。

**验收**：碎片为空不报错；删后撤销能回来；禁用插件后定时器不再触发。

---

### P1-1 `recurring-tasks` 周期任务

**做什么**：管理重复规则（每天 / 每 N 天 / 每周几 / 每月几号），程序启动与每日跨零点时检查，自动 `add_task` 生成到期实例。

**为什么是它**：多篇待办横评把"每周例会、每月总结设一次重复规则"列为核心卖点，FloatPulse 任务模块**没有**这个能力 —— 是明确的功能缺口，不是锦上添花。

**实现要点**：
- 只需 `write`（`ctx.write.add_task(title, note, deadline)`）。
- 规则存 `data_dir/rules.json`；**幂等必须做**：记录"上次生成日期"，避免重复启动生成一堆重复任务。
- 页面插件管规则（增删改），不要用弹窗硬塞。
- 与 `deadline-radar` 天然互补，可共用一套日期工具。

---

### P1-2 `deadline-radar` 截止日盯盘

**做什么**：把"逾期 / 今天 / 本周"的任务浓缩成一张常驻小卡（页面插件 + 悬浮球角标），只显示最近 3 条；提供「顺延一天」按钮。

**为什么是它**：直接对应定位里的「盯截止日」。敬业签/滴答清单的价值核心就是"可见即可管" —— FloatPulse 已有任务分组，缺的是**主动冒出来提醒**这一步。

**实现要点**：
- 只读为主；"顺延一天"需 `manage` 的 `update_task(task_id, deadline=...)`（**其他字段传 `None` = 不动**）。
- 角标数量用宿主 `refresh_badge` 通道，别自己画悬浮控件。
- 分组口径复用 `overdue→today→week→later→none→done`，**不要另写一套**。

---

### P1-3 `daily-standup` 日报/站会生成

**做什么**：按"今天"范围汇总 —— 昨日完成 / 今日计划 / 阻塞项，一键存为笔记。

**为什么是它**：uTools「超级待办」明写"AI 帮你写周报、写日报"；而 FloatPulse 已有 `weekly-report`，**改个时间窗口就能复用九成代码**，性价比最高。

**实现要点**：复制 `plugins/weekly-report/` 骨架 → 时间范围改今日 → 输出模板换三段式 → `ctx.write.add_note()`。约半天。

---

### P2 `focus-review` 专注复盘

读 `ctx.data.pomodoro()` 与任务 `focus_sessions`，按天累计进 `data_dir`，出周/月专注时长与小热力图。价值依赖用户是否真在用番茄钟，故排 P2。

---

## 五、明确不做（附理由）

| 不做什么 | 理由 |
|---|---|
| 翻译 / OCR / 取色 / 计算 / 单位换算 | uTools、Raycast、Flow Launcher 都有成熟件且更好；FloatPulse 无浏览器内核与 OCR 引擎，硬做是劣势区 |
| 全局文件搜索、窗口切换、进程管理 | 已定调交给 Everything / Flow Launcher；与"记完之后"无关 |
| 完整剪贴板历史 | 宿主已有剪贴板收集，插件再做是重复建设（片段库是它的上层，已在推荐里） |
| 云同步 / 多端 | 定位是本机单用户，无服务端 |
| 浏览器书签导入 | 已有「网址导航」面板覆盖 |

## 六、两个前置决策（需要拍板）

1. **网络桥目前只有 POST**（`ctx.http_post_json_async`）。若将来要做"稍后读 / 链接暂存箱"这类需要 **GET 抓网页标题**的插件，必须先给 `src/plugin_net.py` 加 GET 通道 —— 这是宿主改动，不是插件能绕过的。
2. **模拟粘贴要用 `ctypes` 发按键**。依赖白名单允许 `ctypes`（stdlib），但属于"操作其他窗口"的越界行为，需要在插件说明里写清楚，并在 manifest 里声明用途。

---

## 七、建议推进顺序

`daily-standup`（半天，验证页面+write 链路）→ `snippets`（一天，最高频）→ `recurring-tasks`（一天，补缺口）→ `inbox-triage`（两天，独占价值最大但最重）。

# v2 修订（2026-09-28 晚）：三个候选选题的评估

> 用户反馈第一版"没技术含量 / 和宿主重复 / 场景错配"三条成立，并自拟三个选题。以下是对这三个选题的评估与增强建议。第一版的「调研来源」「明确不做」仍然有效。

## 判据修订（在原四条基础上加两条）

5. **交互范式要新**：宿主已有的是「打开页面 → 操作 → 保存」；插件应提供宿主没有的范式（选中即转换、到点主动触发、热键直达）。
6. **有工程深度**：不能是纯 CRUD + 剪贴板，至少要占一样——异步编排 / 解析算法 / 状态机 / 索引 / 冲突处理。

## 候选 1：`ai-text-workshop` AI 文本工坊 —— 值得做，但有两个前置

**形态**：热键呼出对话框，自动带剪贴板文本，一键执行润色/翻译/总结/改语气/提取待办；结果可复制、或 `write` 回写碎片/笔记。

**需求侧**：Raycast AI Commands 确实存在（Pro 的自定义 AI 命令）；PowerToys Advanced Paste 也确实是 PowerToys 的热门功能且已加 AI 增强。但"2025 年公认最热门功能"这个说法**未找到权威出处，标【待核实】**，对外别这么写。

**与 AI 助手是否重复**：**不重复，是范式互补** —— AI 助手是"对话页"（长流程、有上下文、能操控数据），这个是"选中即转换"（单次、无状态、结果即走）。两者可以共存。

**必须解决的两个前置**：

| 问题 | 说明 | 建议解法 |
|---|---|---|
| **后端配置双份** | 后端（云端 base_url/key/model、本地 llama-server 路径/端口/gguf）目前是 `ai-assistant` 私有的。新插件再搞一套 → 用户配两遍、两份 key 不同步 | **不动设置页**（改设置页=用户可见变更+要同步 `verify_settings_groups.py`+进 CHANGELOG）。改为约定共享文件 `float_data/ai_backend.json`，`ai-assistant` 写、其他插件只读并做降级（文件不存在 = 未配置） |
| **本地冷启动延迟** | 本地模式要 QProcess 拉 llama-server，模型加载数秒~十几秒。而"剪贴板一键动作"的价值就是秒级响应，冷启动会毁掉体验 | 分两类动作：①**确定性转换**（JSON 格式化、Markdown↔纯文本、去空行、全半角、大小写）——纯 stdlib、零延迟、不依赖模型；②**AI 转换**——走模型，首次调用给"模型加载中"提示，并记住"本地服务已就绪"状态 |

**增强建议**：把 PowerToys Advanced Paste 里最好用的那一半抄过来 —— **确定性格式转换不依赖模型**，即时响应。这样插件在没配 key、没开本地服务时**仍然有用**（否则它就和 AI 助手一样"不配置就废"）。

## 候选 2：`recurring-tasks` 周期任务 —— 同意，成本最低收益最高，但实现姿势要改

QTimer + `write.add_task` 成本确实极低。但**不能靠"设一个 24 小时定时器"**，有三个坑：

1. **休眠不补偿**：Qt 定时器在系统睡眠/休眠期间不累加，睡一晚回来定时器不会补触发。
2. **程序没启动就漏**：宿主没运行时定时器根本不存在（依赖开机自启）。
3. **重复生成**：宿主重复启动、或规则跨天边界，容易一天生成两条。

**正确姿势 = 轮询 + 补跑 + 幂等**：
- `QTimer` 每 5 分钟 tick 一次 → 比对「当前日期时间」与规则（每天 / 每周几 HH:MM / 每月几号），而不是设一次性定时。
- 每条规则记 `last_fired`（日期），启动时**补跑**错过的（补跑只补最近一次，不无限回溯）。
- 定时器必须在 `on_disable` 里停掉（钩子异常 loader 会隔离，但自己要收尾）。

**"每周五 15:00 自动生成周报草稿并弹 toast"** 这条最有粘性，但要拆清楚：
- 若周报草稿 = **纯模板汇总**（本周新增碎片数 / 完成任务数 / 待办），纯本地可做，零依赖，稳定。
- 若 = **AI 润色后的叙述**，就依赖后端，且本地冷启动同样有延迟。
- 建议：**先做纯模板版**（主动弹 toast + 一键存笔记），AI 润色作为可选增强放在后面。

## 候选 3：`snippets` 快捷短语库 —— 实用，但要加一层才撑得住

这条我第一版推过、后来自己砍了，理由是"技术含量最低、和宿主'临时存'重复"。你的版本有个我没考虑到的点：**只复制到剪贴板，不模拟粘贴** —— 那就不需要 `ctypes` 操作其他窗口，越界风险归零，我上一版在这一条上说重了，纠正。

但要撑得住，建议加 **动态变量**，让它从"静态片段"变成"微型模板引擎"：

| 变量 | 行为 | 技术含量 |
|---|---|---|
| `{{date}}` `{{time}}` `{{weekday}}` | 插入当前日期时间 | 低 |
| `{{clipboard}}` | 插入剪贴板当前内容 | 低 |
| `{{sel}}` | 插入唤出前选中的文本 | 中（要在唤起时抓取） |
| `{{ask:提示}}` | 弹出输入框让用户填 | 中（动态构造表单） |
| `{{py:表达式}}` | 简单表达式求值 | 高（**必须白名单求值，禁 eval 裸跑**） |

再加一条差异化：**从碎片池"升级"成短语**（碎片面板选中 → 存为片段）。这是 Raycast / Espanso / uTools 都没有的，因为只有 FloatPulse 有碎片池。

`{{py:}}` 要慎重：安全上做成"仅允许一组内置函数 + 字面量"的最小求值器，或直接砍掉。

## 修订后的推进顺序

| 序 | 插件 | 工作量 | 理由 |
|---|---|---|---|
| 1 | `recurring-tasks` + 周报主动提醒 | ~1 天 | 成本最低、粘性最高、补"主动性"缺口 |
| 2 | `ai-text-workshop` | ~2 天 | 最值钱（AI 编排 + 双后端 + 回写数据链路），但需先定 `ai_backend.json` 共享方案 |
| 3 | `snippets` + 动态变量 | ~1 天 | 高频但含量最低，放最后；靠动态变量和"碎片升级"拉出差异 |

## 待拍板

1. **后端配置要不要提到宿主层？** 方案 A：`float_data/ai_backend.json` 约定共享（不动设置页，成本低，推荐）；方案 B：进设置页正式配置（要动三件套 + `verify_settings_groups.py` + CHANGELOG，成本高但正规）。
2. **`{{py:}}` 动态求值做不做？** 做就有安全风险需白名单，不做就砍掉。
