# FloatPulse 创意方向（2026-09-27）

> 定位前提：**办公便捷功能集合体**，服务「看到 → 存 → 决定 → 做 → 交付」这条办公动作链。
> 本文不涉及任何知识复习 / 间隔重复 / 记忆算法方向。
>
> 评判标准不是「这个功能好不好」，而是**独占性**——只有同时握有「碎片 + 任务 + 笔记 + 钉图 + 番茄钟」的工具才做得到的事。

## 为什么需要新方向

从 `float_data/` 读出的真实数据：

| 环节 | 数量 | 说明 |
|---|---:|---|
| 碎片收集 | 196 条 | 快捕条 + 剪贴板，全自动 |
| 语义分类 | 196 条（100%） | 全自动，无需人工 |
| 沉淀为笔记 / 任务 | 11 条（**5.6%**） | 6 条笔记 + 5 条任务 |
| 导出进 vault | 0 条 | 功能已实现，从未使用过 |

**断崖出现在「需要人做一次决策」的地方。** 收集端和分类端都是自动的，一到转化端就掉到 5.6%。这不是 FloatPulse 独有的问题，是所有收集类工具的通病——但 FloatPulse 对外讲的恰恰是「记完之后的那一段」，所以这个洞必须自己先填上。

---

## 方向 1 · 工作现场快照（独占性最高）

**一句话**：把「我刚才在干什么」整套存下来，明天一键回到原样。

**痛点画面**
下班前你钉着 3 张参考图、番茄钟跑到第 2 个、刚收了 5 条关于某个客户的碎片。第二天开机——钉图没了，任务躺回列表里，那 5 条碎片混在 196 条里找不着。**桌面还在，注意力上下文丢了。**

**核心机制**
- 「存现场」：序列化当前所有钉图（图像 + 屏幕位置 + 缩放 + 批注层）+ 正在专注的任务 ID 与番茄进度 + 活跃碎片 ID 列表 + 最近 N 条剪贴板
- 「回现场」：钉图按原位置原缩放恢复、任务重新进入专注态、相关碎片在碎片页置顶筛选
- 支持多个命名现场（「客户 A」「周报」），右键菜单切换

**为什么只有 FloatPulse 能做**
它同时握有钉图、任务、碎片、番茄钟四样。**Snipaste 只有图，番茄钟 App 只有计时，Notion 只有文字**——没有任何单一工具同时拥有这四者，所以没有一家能做「完整现场」。

**成本与风险**
成本中。真正的难点在容错：分辨率变化、多屏插拔、钉图源文件已删、任务已被删除——每种都要有明确的降级行为，不能恢复一半卡住。

## 方向 2 · 收件箱清零（inbox zero）

**一句话**：每条碎片必须被显式处置一次，不许无声堆积。

**痛点画面**
就是上面那个 5.6%。剪贴板一直在收，你从来没被要求对任何一条碎片做决定。

**核心机制**
- 新碎片默认进「待处理」状态，球上显示待处理计数
- 处置动作四选一：**转任务 / 转笔记 / 归档（保留已阅）/ 删除**
- 超过 N 天未处置的碎片在快捷卡片上浮出（**限量 3 条、可关闭**，不做全量提醒）
- 处置后自动离开待处理桶

**为什么值得做**
机制本身是 GTD 的标准实践，不独占；FloatPulse 独占的是**处置完之后的落点**——别家的收件箱处置完就结束了，这里处置完直接进入任务 / 笔记 / 导出链路。
另一个附带价值：**处理率本身是一个可以对外展示的数字**。把 5.6% 推到 40%，比任何一句宣传语都有说服力。

**成本与风险**
成本低（碎片加一个状态字段 + 球上计数 + 复用已有右键菜单）。唯一风险是提醒变成骚扰，所以必须限量、可关、不弹模态框。

---

## 方向 3 · 日报 / 周报草稿自动生成

**一句话**：这周干了什么，让工具先写一遍。

**痛点画面**
周五写周报，得翻聊天记录、翻任务列表、回忆周一干过啥。

**核心机制**
选定时间范围 → 汇总已完成任务（按完成时间）+ 该区间碎片（按内容类别分组）+ 番茄计数 → 生成 Markdown 草稿，可直接编辑、复制，或走已有的导出通道。

**独占性**
弱——别人也能做。但**黏性极强**：每周必用一次，是把工具从「想起来才开」变成「固定会开」的最短路径。

**成本**
低。数据全在，纯 Python 模板拼装，无需新依赖。

---

## 方向 4 · 会议 / 电话速记模式

**一句话**：开会时记得快，会后一键成纪要。

**痛点画面**
开会时打字跟不上，记下的散落在便签、微信、脑子里；会后整理成纪要要再花 20 分钟。

**核心机制**
- 速记模式（作为快捷卡片的一个模式）：一行一句，**自动带时间戳**，`@` 前缀标记为行动项
- 结束一键生成会议纪要 md：正文按时间排序，行动项单独成列表
- 行动项可批量转任务（直接复用方向 2 的通路）

**独占性**
中。速记本身不稀奇，稀奇的是**速记结果能直接落到任务和导出链路**——记完不是终点。

**成本**
中。需要一个新的卡片模式 + 纪要模板。

---

## 方向 5 · 「下一步」主动建议（排最后）

**一句话**：球上不只列任务，而是告诉你现在该干什么。

**机制**
根据当前时间 + 任务截止日 + 最近复制的内容，在卡片上推一条「你现在该做什么」。

**为什么排最后**
这是把工具从被动变主动，创意最足，但**极易做成噪音**——推错了就是打扰，用户会直接关掉整个功能。
而且它依赖前几个方向积累的数据密度：碎片没被处置过、任务没在跑番茄钟，就没有任何可推断的依据。**建议等方向 2 落地、数据密度上来之后再评估。**

---

## 推荐顺序

| 顺序 | 方向 | 理由 |
|---|---|---|
| **第 1 个** | 方向 2 收件箱清零 | 成本最低，且直接修补「记完之后那一段」这个自相矛盾的叙事；处理率是可对外展示的硬证据 |
| **第 2 个** | 方向 1 工作现场快照 | 真正抄不走的壁垒，但价值依赖日常使用密度，放在收件箱之后 |
| 第 3 个 | 方向 3 或 4 | 看你自己哪个更痛：周报痛就选 3，会多就选 4 |
| 最后 | 方向 5 | 需要前序方向的数据支撑，且噪音风险最高 |

---

## 一句话总结

现在的 FloatPulse 是「多个便捷功能的集合」，缺的是**让这些功能之间发生化学反应**。
收件箱清零负责让数据流动起来，现场快照负责让四样能力第一次真正合体——这两件做完，它就不再是「一个有很多功能的球」，而是「一个记得你刚才在干什么的球」。
