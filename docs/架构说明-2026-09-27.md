**三条铁律（保持，不要动）**：

| 规则 | 落地方式 |
|---|---|
| UI 不直接读写数据文件 | 面板只调 manager 的公开方法；文件 I/O 全在 `json_store` + 各 manager |
| 颜色只有一处真相源 | `theme.py` 的 `THEMES` 字典 → QSS 模板 `$var` 替换；缺键有 KeyError 兜底 |
| 插件不 import 宿主内部 | 插件只依赖 `src.plugin_api`（契约）+ `src.plugin_ui`（弹窗基类） |

## 三、插件系统：契约与数据流

### 3.1 三个契约对象

```
manifest.json ──validate──▶ 权威元信息（id/name/version/entry/requires/actions/description）
                               │
PluginLoader._load_one(dir)    │
   │                           │
   ├─ 依赖白名单校验 ───────────┤ 仅 PyQt6 + stdlib；显式拒 ssl/socket/requests
   ├─ 定位/导入 entry 模块      │
   ├─ 找 BallPlugin 子类        │
   ├─ 实例化（无参构造）        │
   ├─ ctx = PluginContext.for_plugin(id, dir)   ← 派生绑定身份
   ├─ plugin.create_actions(ctx) ─▶ [BallAction, ...]
   └─ _register_plugin(lp)      ─▶ ActionRegistry.register(act, plugin_id, ctx)
                                      │
                          ┌───────────┴────────────┐
                          ▼                        ▼
                   menu_actions()           hotkey_actions()
                   （右键菜单）              （独立热键线程注册）
```

### 3.2 PluginContext 提供的白名单能力

| 能力 | 形态 | 说明 |
|---|---|---|
| `plugin_id` / `plugin_dir` / `data_dir` | 只读属性 | `data_dir` 首访 `makedirs`，落 `float_data/plugins/<id>/` |
| `logger` | 只读属性 | 写宿主日志 |
| `config` | 只读快照 dict | 插件改不到宿主配置 |
| `data` | `PluginData` 只读门面 | `tasks()/fragments()/notes()/pomodoro()`，一律 deepcopy |
| `show_toast(text, ms)` | 方法 | 宿主气泡提示 |
| `open_main_window()` | 方法 | 打开主窗口 |
| `open_card_mode(mode)` | 方法 | 切悬浮球卡片模式 |
| `parent_window()` | 方法 | 弹窗父窗口（逃生舱，建议只传 parent） |

> **空值语义不一致（已知坑）**：`tasks()/fragments()/notes()` 内部 `or []`
> 返回**空列表**；`fetch()` 返回 **None**。插件判有无数据要看长度。

### 3.3 插件弹窗：必须继承 `PluginDialog`

裸 `QDialog` 会退化成系统原生外观。`PluginDialog(GlassDialog)` 带来：
无边框圆角 + 玻璃壳 + 手绘阴影 + 自绘可拖动标题栏 + **复用主窗 QSS → 主题自动跟随**。

```python
class MyDialog(PluginDialog):
    def __init__(self, ctx, parent=None):
        super().__init__(ctx, title="标题", subtitle="副标题",
                         parent=parent, size=(720, 520))
        card = QWidget(); card.setObjectName("glassCard")   # 可用 QSS 名
        self.body_layout.addWidget(card)                     # 内容必须进 body_layout
        self.add_footer([("取消", "secondaryBtn", self.reject),
                         ("确定", "primaryBtn", self.accept)])
        # ⚠ add_footer 内部已 connect clicked，外部再连会双触发
```

可用 objectName：`primaryBtn` / `secondaryBtn` / `glassCard` / `sectionLabel`
/ `hintLabel` / `settingsSeparator`。**不要臆造** `panelInput` 之类不存在的名字
（`QPlainTextEdit` 等有通用 QSS 规则，不设 objectName 即可）。

## 四、本次架构整理（2026-09-27）

### 4.1 修复：插件加载失败不可感知 ★核心

**问题**：所有失败路径都是 `self._warn(...) + return None`，失败项完全不进
`_loaded`，面板只显示「共 0 个插件」。用户放进一个坏插件后，无从判断是
目录没找到 / manifest 写错 / 依赖被拒 / 代码抛异常——唯一线索是手搜 `app.log`。

**改动**：
- `plugin_loader.py` 新增 `FailedPlugin` 结构 + 9 个 `STAGE_*` 常量 +
  `FAIL_HINTS` 修复建议表 + `stage_label()` 中文标签
- `_load_one` / `_import_entry` 的 9 处失败分支改为 `self._fail(...)`，
  同时写日志**并**结构化留存
- 登记期动作级告警收进 `LoadedPlugin.warnings`；`actions_ok` 记录生效动作数
- 全部动作登记失败 → 记 `STAGE_REGISTER_FAILED`
- 新增公开接口：`load_errors()` / `has_errors()` / `rescan()` / `registry` 属性

### 4.2 修复：插件中心面板能力补齐

- **加载失败区**：失败插件卡片显示「名称 + 阶段标签 + 原因 + 💡修复建议 + 打开目录」
- **单插件启停开关**：调用此前全项目无 UI 入口的 `ActionRegistry.set_enabled`，
  停用后不挂菜单不绑热键，随时可恢复
- **状态标签**：`已启用` / `已停用` / `部分生效 x/y` / `未生效` / `未提供动作`
- **「🔄 重新扫描」按钮**：新放插件无需重启程序即可加载
- 空态在有失败项时隐藏（避免「还没安装任何插件」的误导）

### 4.3 修复：主窗口入口与配置越界

| 项 | 问题 | 修复 |
|---|---|---|
| `show_plugins_page()` | 其余 7 个面板都有，插件页缺失 | 补上，用 `NAV_PAGE_INDEX["plugins"]` 查表而非写死索引 |
| `_CONFIG_RANGES["last_page_index"]` | 上限 7，但插件页索引是 9 → 存不进配置，启动恢复不到该页 | 新增 `config.LAST_PAGE_INDEX_MAX = 9`，写入侧与 `_initial_page_index` 同源 |
| `HELP_PAGE_INDEX` | 说明页索引 8 散落魔数（`index == 8` 两处） | 提为命名常量 |

### 4.4 修正文档错误

`plugins/weekly-report/使用说明.md` 第 3 步写「点『生成草稿』」——实际改范围
即实时刷新，**没有这个按钮**。已改为如实描述，并补插件中心启停入口说明。

### 4.5 修复：install 目录歧义 + 次按钮对比度 ★截图驱动

用户实机截图暴露的两个观感问题，都已定位到根因：

**（1）插件装在哪——概念容易混**

`<base_dir>/plugins/`（**安装位置**）与 `float_data/plugins/<id>/`（**插件私有
数据**）是两个不同目录，光看名字极易搞反。修法：

- 插件中心页顶部新增一行 **`📂 插件安装目录：<绝对路径>`**（等宽字体、
  可选中复制），拿不准就照抄
- `docs/插件开发说明-2026-09-26.md` 加一张两者对照表，明确「装插件放 `plugins/`，
  插件的数据落在 `float_data/plugins/`」

> 实测确认（源码运行）：`PluginLoader.plugins_dir` = `D:\桌面\AI Port\FloatPulse\plugins`，
> 与用户预期完全一致；用户截图里的「加载失败」是**刻意为可诊断而展示**的
> （失败区会给出阶段 + 原因 + 修复建议），不是把插件放错了目录。

**（2）次按钮文字在浅色主题下几乎看不见**

`secondaryBtn` 一直是「淡青底（`$primary_a12`）+ 青色文字（`$primary`）」。
浅色主题 `$primary = #5BC0BE` 明度偏高 → 实测对比度仅 **1.9:1**，而 WCAG AA
正文要求 4.5:1。影响面：**10 个模块 39 处**次按钮全看起来像禁用态，
新增的插件中心（每卡 3–4 个次按钮）把这个缺陷放大了。

修法：新增主题词 `secondary_text`，浅色取同色系加深的 `#27787A`（**4.6:1**），
深色保持 `#6FFFE9`（本就 9.7:1）。QSS 里 `QPushButton#secondaryBtn` 与
`:checked` 两处 `color: $primary` → `color: $secondary_text`。
新增 2 条护栏测试（token 齐全性 + 对比度下限 + QSS 未回退到 `$primary`）。

| 主题 | 修复前 | 修复后 |
|---|---|---|
| light | 1.92:1 ❌ | **4.60:1** ✅ |
| dark | 9.66:1 ✅ | 9.66:1 ✅ |
