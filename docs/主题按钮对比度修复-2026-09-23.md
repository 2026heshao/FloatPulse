# 主题按钮文字对比度修复 — 2026-09-23

## 起因

截图反馈：任务页「➕ 添加」、笔记页「＋ 新建笔记」按钮**文字看不清**。
（薄荷色底 + 白字）

## 根因

`src/theme.py` 基础规则：

```css
QPushButton {
    background-color: $primary;
    color: white;          /* ← 问题在这 */
}
```

主题里 `$primary` **本身就是浅色**：

| 主题 | `$primary` | 白字对比度 |
|------|-----------|-----------|
| dark（默认） | `#6FFFE9` 极浅薄荷 | **1.22:1** |
| light | `#5BC0BE` 中亮青 | **2.16:1** |

合格线 4.5:1。不是某条规则写错，而是**"主色即深色"的直觉在本项目恰好相反** ——
主色是用于高亮/CTA 的亮色，压在上面的文字必须是深墨。

## 影响面（同族错误共 8 处）

| 选择器 | 落点 |
|--------|------|
| `QPushButton`（基础） | 任务页「＋ 添加」、笔记页「＋ 新建笔记」等所有未命名按钮 |
| `#primaryBtn` | 碎片编辑「保存修改」、碎片面板「复制全部内容」、玻璃弹窗「复制」、合并预览「复制到剪贴板」、设置页「保存设置」 |
| `#taskAddBtn` | 小卡片任务添加、网址导航「添加站点」 |
| `#nextBtn` | 小卡片「下一个」 |
| `#modeBtn:checked` | 卡片模式切换选中态 |
| `#tableOpenBtn:hover` | 表格「打开」悬停 |
| `#navSiteBtn:hover` | 站点卡片悬停 |
| `#fragCopyBtn:hover` | 碎片复制悬停 |

另有 `QPushButton:disabled` 在浅色主题下是 `#C0C8D0` 底 + 半透明白字（1.69:1），
一并处理。

> 有意思的是 **hover 态早就有人改对了**（6 处硬编码 `#1B2B33`），
> 说明当时是"看到哪改哪"，没把"主色底上的文字色"抽成主题词。

## 修法

`src/theme.py` 新增两个主题词（**light / dark 两份字典都要加**，
QSS 走 `Template.substitute` 严格模式，缺键直接 `KeyError`）：

```python
"on_primary":  "#1B2B33",              # 主色底上的墨色（两主题同值）
"on_disabled": "#6B747E",              # light
"on_disabled": "rgba(255,255,255,180)",# dark
```

把上述 8 处 + disabled 的 `color: white` / 硬编码 `#1B2B33` 全部换成主题词。

`src/tasks_panel.py`：`➕ 添加` → `＋ 添加`。
**emoji 图标不吃 QSS 的 `color`**（走彩色字形），全角「＋」才能与文字同色。

## 效果（实测对比度）

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 深色·基础按钮常态 | 1.22:1 | **11.91:1** |
| 深色·hover | — | 12.26:1 |
| 深色·pressed | — | 5.17:1 |
| 浅色·基础按钮常态 | 2.16:1 | **6.76:1** |
| 浅色·hover | — | 11.91:1 |
| 浅色·pressed | — | 4.56:1 |

## 护栏

新增 `tests/test_theme_contrast.py`（11 项）：

1. `on_primary` / `on_disabled` 必须在两份字典里都存在且非空
2. `on_primary` 对 `primary` 的对比度 ≥ 4.5
3. **通用护栏**：任何浅色实底（相对亮度 > 0.6）不得压白色/近白文字
   —— 覆盖全部 8 处同族错误，且不误伤深红底白字的 danger 按钮、
   语义发灰的 disabled 态；渐变按 `stop:` 色标一起判，避免 `primaryBtn` 钻空子
4. 基础按钮 primary/hover/pressed 三态对比度 ≥ 4.0
5. 边界守卫：danger hover 保持白字、disabled 使用 `on_disabled`

**负向验证**：把 `on_primary` 改回 `#FFFFFF` → 护栏立即失败
（`assert 2.16 >= 4.5`），确认护栏真的在工作，不是摆设。

> 就是这条护栏抓出了「新增了 `on_disabled` 主题词但忘在规则里使用」的漏改。
